# 光栅画的阴影 #geometry 

![[Pasted image 20261006132821.png]]

我们之前讨论着色的时候 当下的着色过程是一种非常局部的过程。每个点只考虑它自己和光源还有摄像机的关系 并没有考虑它和其他点之间的关系 比如说遮挡之类的


如果在3D场景中不渲染阴影的话 就会使人感觉东西没有接触地面 像浮在半空中一样。这是人在漫长进化中形成的一种感知：只要看见了在地上投下的阴影 就好像人走在地面上


![[Pasted image 20261006133338.png]]

核心的思想是：不在阴影中的点 一定是可以被摄像机看到 并且也能被光源看到的点



在这里讨论的都是点光源或者方向光源生成的阴影 也就是说 硬阴影会有明显的、很硬的一条边界。软阴影的情况之后再说

软阴影就是投影出来的阴影 边缘会变得比较柔和一点


![[Pasted image 20261006133831.png]]

第一步 将摄像机从光源的角度出发看向场景 生成一幅深度图。不需要渲染出来 只需要深度就可以

![[Pasted image 20261006134040.png]]

第二步就是正常进行光栅化渲染 将每个点转换到光源所在的摄像机空间内 去寻找这个点。如果该点被光栅化 对应的深度值是多少？如果相等 说明可以同时被眼睛和光源看到；其他情况就是阴影的情况

![[Pasted image 20261006134153.png]]

| Y   | Y        | 非阴影 |
| N   | Y        | 阴影  |

所以，这个算法讨论的只是前两种情况，即必须被 camera 所看到的场景。在这个被 camera 看到的前提下，分为光能看到的 Y 和光看不到的 N：
1. 光如果能看到，就是非阴影；
2. 光如果看不到，就是阴影。

# 基础的ray tracing算法 #ray-tracing 



![[Pasted image 20261006143154.png]]

在研究算法之前，先对光线进行定义。在 Ray Tracing 算法中，有以下假设：
1. 光线被认为是沿直线传播的。
2. 不同的光线相遇时，不会发生任何碰撞改变。
3. 光路的可逆性：假如光线从光源射到墙上，反射到地上，经过各种各样的反射，最终到达人的眼睛，这样就形成了一条光路。那么就可以反过来理解，即从眼睛发射出一条感知的光路，弹到地上，再弹到墙上，最后弹到光源上。




![[Pasted image 20261006143436.png]]

在科学未蓬勃发展的以前 有一种理论是说 我们看到东西是从眼睛散发出 feeling rays 碰到物体被遮挡之后 然后感知到了物体 并且还得到了一众名人的支持。这虽然是不对的 但也说明了描述这种现象的一种简洁的方式。For every complex problem  there is an answer that is clear  simple and wrong

但这也是光线追踪的一种讲法 也是“追踪”（trace）一词的来历：就是我们从观察者的角度出发 去追踪光线的来源 根据光路的隔离性

![[Pasted image 20261006143749.png]]

从眼睛散发出的光线叫 Ray Casting。投射光线的过程如下：

1. 从观测点到屏幕的每个像素进行连线，投射出一条光线。
2. 当投射出的光线打到物体上之后，再从该点与光源进行连线，检测是否能被光源所看到。
3. 若看不到，则为阴影；若看得到，就计算这条光路上应该有多少能量，最终进行颜色的计算。


![[Pasted image 20261006230951.png]]

对于显示 mesh 表面的求交 就用光线和三角形的求交来做 因为三角形是最最基础的表面形式

这种方式可以判断点是否在模型内部或外部，这应用到了拓扑里面的知识：

1. 如果你在模型内部，随机向外打一条射线，和模型一定相交，且有奇数个交点。

求光线如何与三角形求交，分成两个步骤：
1. 先判断光线与三角形所在平面的交点；
2. 再判断这个交点是否在三角形内部。

通过一个法线和一个点的位置即可定义一个平面。因为平面上的任何一条线段 都可发现其垂直于该法线 这也包括从 P 到 P' 的所有线段

判断平面上的点是否在三角形内 在最开始讲叉乘的时候也已经讲过了


它是人们发现的一种更高效的方式 可以同时求出交点 又判断是否在三角形内

第一个式子是光线到重心坐标的表达式。其中，重心坐标是两个未知量 B1、B2，光线是一个未知量 T。经过一个法则就可以得到左边的矩阵形式，从而可以求解出 T、B1、B2。

最后满足的条件是：T 是正数，B1、B2 都在 0~1 的范围内。这说明找到了一个和三角形相交的点。

我们从二维的简化角度来看光线与 AABB 的交点计算：

首先，射线在 Y 轴上求交，得到 tmin 和 tmax；
然后，射线在 X 轴上求交，得到 tmin 和 tmax；
最终得到一段 [tmin, tmax]，即射线进入盒子到离开盒子之间的一段。

这一段刚好是前面的两段的intersection 
交集

为什么要求交集？因为你先前的两步计算的是两个对面分别形成的线段。由于这个矩形是这两个对面的交集 所以将前面分别求出的两条线段进行求交 就得到了光线经过该方形的线段




![[Pasted image 20261007102508.png]]

对于 3D 来说，我们考虑这样一个逻辑：光线进入盒子，必须是进入了所有的面才算进入了盒子；光线离开盒子，只要离开一个面就算离开了盒子。

所以算法就是：我们对每一个面都求出它的 t_min 和 t_max，然后最后计算：
1. T_enter：所有 t_min 的最大值。因为你要让光线进入所有的面。
2. T_exit：所有 t_max 的最小值。因为你只要离开一个面，就算离开盒子。

最后比较 t_enter 和 t_exit 如果有意义的话 且 t_enter < t_exit 我们就能确定这个光线确实在盒子中传播了一段距离

![[Pasted image 20261007102941.png]]

我们再完整地解释一下这个算法的其他情况：

1. 如果 TX < 0，说明盒子在光线的背后，肯定没有交点。
2. 如果 TX ≥ 0，但是 T < 0，说明这个点在盒子内部，它在负的时间进入了盒子，在正时间离开了盒子，所以一定有交点。

综合起来，光线和 AABB 有交点，当且仅当 t_enter < t_exit，并且 t_exit ≥ 0。



![[Pasted image 20261007103213.png]]

使用 AA 的方式在运算量上有优势。如果盒子是任意旋转的，就需要用第一个式子来求，运算量很大。

如果是 AABB 的话，比如看下面这个面是垂直于 X 轴的，所以我们去求的时候，就只需要求 X 轴方向的法线、X 轴方向的分量就可以了。
