# 布林缝中的高光模型 #computer-graphics 

生活中我们观察到，高光的物体都有点像镜面材质的感觉， 
表面比较光滑的那种。观察到的高光位置，其实是那些材质本身有一个特性：它反射出来的光不像漫反射一样向四面八方 360° 扩散，而是集中在入射角对应的出射线周围，和镜面反射方向有一定的分布，在镜面反射方向附近


![[Pasted image 20260912102420.png]]


当V和R比较接近的时候，越近高光程度越强

![[Pasted image 20260912102721.png]]

这个模型采用了一种取巧的计算方法，就是使用了一个半程向量 H（它是 I 和 V 的中间向量），因为如果直接计算 R 的话会比较复杂一点。

R 和 V 的夹角刚好等于上图中半程向量和法线 N 的夹角 α 的一半，它们是等比的：R 和 V 的夹角越大，上图中 N 和 H 的夹角 α 就越大。


需要注意的是，公式里面的 KS 和之前的漫反射是一样的。最后面使用了 cos 的只计算，加上了一个 chi 参数。

chi 参数指的是高光散布的一种聚集程度。比如说像镜面的话，就是非常窄的，窄的幅度在镜面反射方向；但是像其他不那么粗糙的材质，在镜面反射角周围。


布林模型是一个经验模型，它不讲究完全物理上的可信度。在镜面反射这里，和前面有一点点的出入。

比如说，在考虑漫反射的时候，不仅考虑了光传过来的能量大小（即 I/R²），还考虑了 L 和 N 的夹角导致的多少能量真正照在平面上的 cos 值（L·N）。但是在高光这里，却没有考虑这一项。

半成向量N点乘H，它只考虑了镜面反射光的多少

所以它是一个经验模型，这个式子里只表示是否有高光，没有考虑本身自己照到了多少光





![[Pasted image 20260912124928.png]]

在计算高光项时，上面有一个指数 P。它的含义是：cos 已经可以衡量两个向量的夹角是否足够接近，但是它的容忍度很高。

比如在第一幅图中，夹角为 45° 时感觉已经离得很远了，但在 cos 的计算中，结果仍有 0.6 左右的大小。如果直接用于高光计算，会出现一个特别大的高光亮片。

如果加上指数 P，会将这个曲线变得越来越收紧。一直到第四幅图时，曲线就收紧到几乎只贴着纵轴。这个时候，微小角度的变化就会导致高光急剧衰减。


大家正常使用 blimp 模型的时候，通常将这个值调到 100 左右，就相当于只要有微小的角度变化，这个高光就会消失

# 武林风模型中的环境光照 #computer-graphics 

![[Pasted image 20260912125433.png]]

这一项也非常简单，只是用一个值来近似从环境中得到的漫反射光

这一点和漫反射本身的反射倒是挺有意思的，是相反的。考虑漫反射中，我们看到的是从点箭头向外发散的一圈；但是你从环境光接收到的，就相当于很多条线，360°球体聚集向点形成的一种效果


所以从这种假设上来看：
1. 计算和光源的方向没有关系：因为你接收到的是来自四面八方周围环境不断反射过来的光。
2. 和观察角度也没有关系：因为你这里假设环境光是四面八方平均来的，所以从每个角度观察下来，情况应该是一样的。
而且和法线方向也没有关系


所以环境光来说，它就是一个常数，这是一个非常大胆的假设

# 着色频率 #computer-graphics 

![[Pasted image 20260912130357.png]]

模型是一模一样的，但是不同着色过程却产生了不同的效果

这是着色频率带来的差异

第一个图是对每个面进行着色。每个面有一个法线方向，以此为依据来进行 shading 的计算，得到的结果应用于整个面


第二个图是对每个顶点进行着色，计算每个顶点的法向方向，然后面的值取 4 个顶点的 lerp 值

不是4个顶点，是3个顶点，用三角形的差值算法来做

第三个图是对每个像素进行一次着色。也就是说，每个三角形进行光栅化之后，每个顶点有自己的法线方向。三角形内部的每个像素点都通过插值法，得到了一个法线方向，这个方向是 3 个顶点法线方向的插值


![[Pasted image 20260912131015.png]]

第1种情况叫 flat shading，就是对每个三角形进行着色，每个三角形中通过叉乘可以得到法线方向

# 计算主顶点过程中顶点的法线 #computer-graphics 

![[Pasted image 20260912132355.png]]

顶点的法线：一个顶点周围连接着几个面，它的法线方向就是周围临接面的法线方向的平均值

可以理解为多个向量的平行四边形法则。因为如果只连接两个面，很直观的就是两个法线方向的平均值

其实这种做法是一个比较简单粗略的做法，如果对周围的面积做面积加权，会更加准确一点

# 渲染管线 #computer-graphics 


![[Pasted image 20260912195811.png]]

把所有前面所讲的东西串在一起，这个东西就叫做图形管线

更好的名称应该叫实时渲染管线，它是针对实时渲染来做的

渲染方法有很多，实时渲染只是其中的一类


![[Pasted image 20260912200135.png]]

我们整个管线的输入是 3D 空间中的点的定义，中间经过 Vertex Shader 变换到屏幕空间下，然后进行三角形、片元的组装，进行光栅化变成 Fragment。Fragment 在不考虑 Multi-sampling 的情况下，可以认为是一个像素。接着通过 Fragment Shader 得到处理后的结果，最后整体结果在 Frame Buffer 中显示出来

整个pipeline过程几乎已经全部写入了显卡的硬件中


为什么三角形化是在后面那一步呢？

是因为我们在定义模型的时候可以这样定义：先定义模型中所有用到的点，再定义哪些点会组成三角形。即使将其变换到屏幕空间，这种关系也不会改变，这类似于 vertex buffer 跟 index buffer。

所以，三角形化在哪个步骤进行都是可以的，但在屏幕空间变换之前进行是比较省力的。

核心在于，我们希望定义一个物体上==任意一个点它自己的属性==，而不是说整个物体都是同一个属性，这就是纹理起到的作用

无论你使用到的纹理是什么，无论是法线还是凹凸，还是其他别的

任何三维物体的表面其实都是二维的。比如从球体的表面积公式来看，它只和 R 的平方有关，这相当于圆形平面的面积，圆形平面的面积也和 R 的平方有关

物体是三维的没错，但是它的表面是一层一层面，相当于就是一个二维的层面
“面”这个词就是二维的意思，“体”才是三维的意思，“表面”就是表面的一层二维的东西

我们怎么定义表面？

这个表面可以用一个二维平面来表示，也就是纹理空间（texture space）中的一个表面。三维物体中的任何一个表面，都可以映射到这个总体的表面中。

这也就是在游戏开发中，使用纹理图集（texture Atlas）将所有小的纹理图片组合成一整张纹理图片的原理：它将场景中所有物体的表面，全部摊开在一个纹理空间中。


所以这也是映射（mapping）的含义所在，它将三维空间表面中的点映射到我们预定义好的一张二维平面中


![[Pasted image 20260912235404.png]]

所以这也是我们在3D软件中使用UV的原因：就是将我们建立的一个体，使它的表面展开成一个二维的形式，方便我们去做映射。上图中右上角的图，应该是从三维软件中整体导出的时候做出来的一张图

当我们思考空间表面到二维平面纹理的映射时，可以从最基本的三角形单元来看：

左图中的三角形存在于立体的表面中，右图中的三角形则存在于纹理空间中的一个区域。

可以看到，三角形的密度是不一样的。空间中相同大小的三角形，在二维的 texture 平面中可能有的大有的小，而且还会发生变形。

![[Pasted image 20260912235826.png]]


所以，空间中表面的每个点都有一个纹理的坐标，这个坐标是二维的，我们将其称为 UV

从这张图中点的密度也可以观察到，将三维中的点展开到二维的话，会产生一些挤压和拉伸的变化。在三维中，点分布得非常均匀，但是展开到二维平面上，有的地方挤，有的地方稀疏

# Texture和material的区别 #computer-graphics 

所以到这里，终于理解了纹理和材质本质的区别在哪里：

1. 纹理：是用来表现三维物体表面任何一个点属性的二维图像。
2. 材质：是对整个 render pipeline 而言的，它包含了一些可控的参数，这些参数共同组成了三维物体的材质。因为改变任何一个参数，都会改变最终的渲染效果。

那么，这些材质参数如何修改呢？
你可以让整个物体只使用同一个参数；或者让物体上的每个点使用不同的参数。而“每个点使用不同的参数”如何实现呢？就需要使用纹理来实现。

所以，这就是它们两者的关系。
