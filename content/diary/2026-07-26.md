
# 游戏开发方向 #game-dev

直接 follow 《Handmade Hero》是一个长期且慢速的过程。现在自己对于游戏开发领域的知识理解得还不透彻，很多名词、很多技术都不清楚。

我建议下一步可以快速将《Handmade Hero》里面的视频过一下，看看有哪些知识点，然后分别对每个知识点做小的 demo（比如物理、动画、渲染之类）。理解了这些知识之后，才更容易地去统合，做一个完整的游戏。

# handmade 的代码思路、风格 #game-dev 

Handmade 的代码方式是直接写 dirty code。比如有一个小想法，就直接用 dirty code 去解决，而不是构想一个完整的系统方案。

因为一直处于探索阶段，探索一个东西的可行性并不一定会最终采纳。所以先做一个简单的实现测试，把手感反馈出来。它主要的目的是激发你后续的灵感，这只是一个过程，不是最终的代码。最终的代码需要重构成为工业级强度的稳固代码。

这是一种在技术手段比较高超的时候可以使用的方式，思路非常灵活，只有想不到，没有做不到。

很多时候，即使你有了更高级的知识储备，也不一定在探索阶段全部用上去。比如在《Handmade Hero》中，对角色踩上楼梯的上下进行反应，如果你想做一个完整的 3D 斜面碰撞处理去解决这个事情，那花费就太大了。

如果用简单 dirty 的方法去解决，而不是完整的 3D 处理方案，你可以快速地检测出手感。你在操作时看到角色与环境真实的变化状况，才能知道你想要的效果和实际效果之间的区别，从而激发你下一步的动作。这是快速迭代过程中给予你非常重要的东西。

至于这些 dirty work 或 code，后期可以通过重构慢慢地替代掉。

还有最重要的一点，它锻炼了你灵活变化的能力。即使你的代码库不是模块化的，你也要根据实际要求进行动态改变，去克服这样的心理：写程序不应该恐惧改变，总担心改变了这一点并不完整，会引入新的 bug。

但目前我们处于探索期，还没有引入完整的测试，所以只要在画面中看到合适的效果即可，不用担心深层次的 bug。只需把代码当成一块可塑的泥块一样，随时摆弄。

# 如何才能做成功的游戏 #game-dev 

首先，不要只关注游戏开发，也要关注游戏设计和游戏审美。你想要的游戏、你喜欢的游戏是什么？是怎么做到的？把设计层面的东西搞清楚，用设计层面的东西去指导开发。


其次，借用其他人的话：快速地做完你的前10个游戏，因为它们都是垃圾。不要幻想着第一次做游戏就能成功，而是要快速地去迭代，从中发现问题，这样才能从失败中得到经验，最终孕育出成功的游戏。
