# AngelScript 完整优缺点详解（面向 C++ 自研游戏引擎）

AngelScript 是**专为 C++ 引擎深度绑定设计的静态强类型嵌入式脚本**，定位清晰：主打**C++ 同源、类型安全、跨语言调用高效、主机 / 单机稳定**，是 3A、主机、PC 单机引擎的优质脚本，下面分**核心优点、核心缺点、适用场景总结**三部分完整说明。

## 一、核心优点（核心竞争力，Lua/LuaJIT 难以替代）

### 1. 语法高度贴合 C++，上手与代码迁移成本极低

1. 语法、关键字、运算符、流程控制、类、重载、命名空间几乎复刻 C++，C++ 程序员几乎零学习成本，不用适应全新脚本语法AngelCode。
2. 脚本逻辑后期热点优化，可以**直接把 AS 代码平移改成 C++**，改动极小，是所有脚本里迁移最顺滑的语言。
3. 团队可以统一编码规范，底层 C++ 与上层脚本风格一致，沟通、维护门槛远低于 Lua、JS。

### 2. 原生静态强类型，大型项目稳定性碾压动态脚本

1. **编译期做完整类型检查**：变量类型、函数参数、返回值、类继承错误，在脚本编译成字节码阶段直接报错，**不会把类型隐患带到游戏运行时**，从根源规避弱类型语言常见的 nil、类型隐式转换、参数传错等隐性 BUG。
2. 原生完整 OOP 体系：单类继承、接口多实现、函数重载、运算符重载、访问权限控制，面向对象架构规范统一，适合大型游戏组件、ECS 架构长期开发。
3. 变量内存布局固定，内存行为可预测，长时间游戏运行的稳定性远优于动态类型脚本。

### 3. C++ 双向绑定原生天花板，无需第三方库，互调性能优异

1. **自带完整绑定 API，无第三方依赖**，直接注册 C++ 全局函数、成员函数、类、枚举、引用、const 属性即可使用，不需要 tolua、sol2、pybind 这类第三方胶水库，从零写绑定工作量远小于 Lua 体系。
2. 支持**脚本直接继承 C++ 导出的基类**，完美实现 C++ 基类、脚本子类的多态调用，这是 Lua 完全做不到的核心优势，引擎组件架构天然契合。
3. 采用原生调用约定直访 C++ 函数，**没有 Lua 栈压栈弹栈的开销**。游戏帧循环高频次 C++ 与脚本互相调用时，开销更低、帧率更稳；只有 LuaJIT 的 FFI 能勉强追上单向调用，C 反向调用脚本依然弱于 AS。
4. 内置**Object Handle（对象句柄）**，等价于 C++ 智能指针，天然管控跨语言对象生命周期，野指针、内存泄漏、悬空引用问题更容易管控。

### 4. 内存管理可控，GC 机制成熟，抖动易于管控

1. 基础采用**引用计数**处理常规对象，搭配**增量式迭代 GC**专门解决循环引用，GC 可以手动暂停、手动触发、限定执行时长，开发者可以把 GC 安排在场景切换、帧空闲间隙，轻松规避主线程卡顿尖峰。
2. 内存占用走势高度可预判，不像 LuaJIT 的 JIT 编译、动态 table 扩容带来不可控的内存波动，非常适合主机平台硬实时帧率要求。
3. 开发者可以完全接管内存分配器，对接引擎自带内存池、内存追踪系统。

### 5. 原生完善沙箱、多线程、安全机制，适合 MOD 与多线程引擎

1. **原生权限沙箱**：脚本只能访问引擎主动注册暴露的接口，可精细限制文件读写、内存、执行时长、函数权限，做玩家 MOD、第三方插件脚本、防外挂的先天优势极大，Lua 沙箱需要从零手写封装AngelCode。
2. 多线程设计友好：**每个虚拟机实例天然线程安全**，多线程逻辑只需要新建独立 VM 即可，不用像 LuaJIT 单 VM 完全非线程安全，必须做多进程 / 多 VM 隔离。
3. 全平台字节码执行，**不存在 JIT 平台限制**：iOS、PS、Xbox、Switch 等封闭主机系统禁止动态 JIT，AngelScript 性能全程稳定，不会像 LuaJIT 禁用 JIT 后性能大幅跳水。

### 6. 本地编辑器热重载体验顶级，开发迭代效率极高

1. 支持模块动态编译、卸载、替换，编辑器 PIE 运行游戏时，**保存脚本即可即时重载逻辑**，无需重启编辑器、重启游戏进程，是《双人成行》等 3A 项目的核心开发利器。
2. 编译速度极快，增量编译毫秒完成，游戏玩法、AI、技能逻辑调试效率远超 C++ 全编译，也优于 Lua 文件重载的架构限制。

### 7. 官方文档完善，长期稳定维护，工业可靠性强

自 2003 年持续维护二十余年，官方手册详尽，论坛响应稳定，SDK 附带序列化、调试、字符串、容器全套扩展插件，代码质量高，极少出现底层虚拟机 BUG，适合商用长线项目。

## 二、核心缺点（选型决定性短板）

### 1. 远程线上热更新生态极度贫瘠，完全不适合国内手游热更场景

1. 它**只擅长本地开发热重载**，**移动端线上远程热更新没有成熟商用方案**。想要做线上游戏不停服下发逻辑补丁，需要自己从零实现模块重载、对象状态序列化、旧实例迁移、内存兼容处理，开发难度极高，没有像 XLua、Tolua 那样现成、经过海量手游验证的成熟框架。
2. 静态类型的类结构固定，运行时修改类成员、新增字段、重构架构难度远大于 Lua 动态 table，大规模热补丁天生弱势。

> 简单直白：做单机编辑器热重载无敌，做手游线上热更就是硬伤。

### 2. 社区小众，生态单薄，人才与第三方资源稀缺

1. 社区高度垂直，仅聚焦 PC / 主机单机、3A 自研引擎，受众远小于 Lua，全网教程、开源工具、通用第三方库（网络、加密、配表解析、协程框架）数量极少，大部分通用工具需要团队自行封装。
2. 市面上熟练 AngelScript 的程序员数量很少，招人难度、人力成本远高于 Lua 开发人员，外包、策划上手门槛更高。

### 3. 动态灵活性不足，缺少动态容器，配置型场景开发效率偏低

1. **没有 Lua 的万能 Table 动态字典容器**，所有容器、结构体都必须提前定义静态类型，运行时无法随意动态新增键值，处理策划配置表、临时动态数据、灵活异构数据时，写法繁琐，效率不如 Lua。
2. 原生不支持便捷的匿名 Lambda、闭包、灵活函数式写法，回调、异步逻辑写法相比 Lua、TS 更啰嗦。
3. 不支持 C++ 多重继承，仅能用接口变相实现，部分复杂架构需要额外设计绕路。

### 4. 极致纯数值运算性能上限弱于开启 JIT 的 LuaJIT

在纯脚本内部密集循环、大规模浮点数学运算场景，开启 JIT 的 LuaJIT 执行速度可以达到 AS 的 1.2~2 倍，极限性能更强；AS 全程字节码解释执行，没有 JIT 编译加速，纯脚本计算的天花板略低。
 （但游戏常态的跨语言互调场景，AS 依然占优）

### 5. 虚拟机体积更大，极致轻量化嵌入式场景略吃亏

完整 AngelScript 虚拟机体积约 250KB，远大于原版 Lua（几十 KB）、LuaJIT（90KB）。针对超小型 2D 小游戏、低端嵌入式设备、极致精简包体的项目，内存与体积占用不如 Lua 轻巧。

### 6. 生态偏向游戏引擎，通用编程库几乎空白

Lua 可以兼顾客户端、游戏服务器、工具脚本全场景通用；AngelScript 几乎只能用于游戏引擎嵌入，服务器、通用脚本领域完全没有生态，无法实现客户端服务端脚本代码复用。

## 三、优缺点总结 & 精准选型结论

### 适合选 AngelScript 的场景

1. 自研**PC 单机、主机游戏、3A 大型引擎**，看重长期工程稳定性、代码可维护性；
2. 团队主力为 C++ 程序员，想要脚本与底层代码风格统一，方便热点逻辑回退 C++ 优化；
3. 核心诉求是**编辑器本地热重载快速迭代**，不需要手游远程线上热更新；
4. 需要开放玩家 MOD、第三方脚本，对权限沙箱、线程安全、防外挂有高要求；
5. 全平台包含主机平台，需要所有平台性能表现完全一致。

### 不适合选 AngelScript 的场景

1. 国内安卓手游、网游，必须依赖成熟远程热更新方案；
2. 小型团队、小游戏，追求快速开发、低成本招人、复用现成第三方脚本框架；
3. 需要脚本同时兼顾客户端 + 游戏服务器共用；
4. 大量动态配置、异构数据表，极度依赖动态容器快速开发。

### 折中经典方案（Urho3D 开源引擎标准架构）
