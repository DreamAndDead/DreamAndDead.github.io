## 智能指针和 `new` 的关系

智能指针和 `new` 的关系可以概括为：**智能指针是为了管理 `new` 创建的对象而存在的**。但现代 C\+\+ 中，它们的关系发生了演变。

---

### 1. **传统关系：智能指针管理 `new` 的对象**

智能指针最常见的用途就是**接管 `new` 出来的裸指针**，自动负责 `delete`。

cpp

```cpp
// 传统方式（危险）
int* raw = new int(42);
// ... 可能忘记 delete，导致内存泄漏
delete raw;

// 智能指针接管（安全）
std::unique_ptr<int> ptr(new int(42));  // ✅ 自动 delete
// 离开作用域时自动释放内存
```

**核心思想：** 将 `new` 创建的资源交给智能指针管理，实现 **RAII（资源获取即初始化）**。

---

### 2. **现代 C\+\+ 最佳实践：避免直接使用 `new`**

从 C\+\+11 开始，**强烈建议不要直接使用 `new`**，而是使用 `std::make_unique` 和 `std::make_shared`。

cpp

```cpp
// ❌ 不推荐：直接 new
std::unique_ptr<int> ptr1(new int(42));
std::shared_ptr<int> ptr2(new int(42));

// ✅ 推荐：使用 make 函数
auto ptr1 = std::make_unique<int>(42);
auto ptr2 = std::make_shared<int>(42);
```

#### 为什么避免直接 `new`？

| 问题 | 说明 |
| --- | --- |
| **异常安全** | `new` 和构造函数之间的异常可能导致泄漏 |
| **重复代码** | 类型名出现两次（`std::unique_ptr<int>` 和 `int`） |
| **性能** | `make_shared` 一次分配，`new` 需要两次分配 |

**异常安全问题示例：**

cpp

```cpp
// ❌ 危险：可能泄漏
process(std::shared_ptr<Widget>(new Widget()),
std::shared_ptr<Widget>(new Widget()));
// 如果第二个 new 抛出异常，第一个 Widget 泄漏

// ✅ 安全：make_shared
process(std::make_shared<Widget>(),
std::make_shared<Widget>());
```

---

### 3. **仍然需要使用 `new` 的例外情况**

虽然应该避免，但有些场景必须使用 `new`：

#### 3.1 自定义删除器

cpp

```cpp
// 需要自定义删除器时
auto deleter = [](FILE* f) { fclose(f); };
std::unique_ptr<FILE, decltype(deleter)> ptr(fopen("file.txt", "r"));
// 这里 fopen 返回裸指针，相当于 new FILE
```

#### 3.2 前向声明类型（不完整类型）

cpp

```cpp
// Widget.h
class Widget;  // 前向声明

// 不能使用 make_unique，因为 Widget 不完整
std::unique_ptr<Widget> ptr(new Widget());  // ✅ 可以
// auto ptr = std::make_unique<Widget>();   // ❌ 编译错误
```

#### 3.3 旧代码库兼容

cpp

```cpp
LegacyAPI* raw = legacy_create();  // 返回裸指针
std::unique_ptr<LegacyAPI, Deleter> ptr(raw);  // 用智能指针接管
```

#### 3.4 自定义内存分配器

cpp

```cpp
std::unique_ptr<Widget> ptr(new (pool.alloc()) Widget());
// make_unique 不支持自定义分配器
```

---

### 4. **智能指针的构造方式对比**

| 智能指针 | 直接 `new` | `make` 函数 | 区别 |
| --- | --- | --- | --- |
| **unique\_ptr** | `unique_ptr<T>(new T())` | `make_unique<T>()` | 推荐 make，更安全高效 |
| **shared\_ptr** | `shared_ptr<T>(new T())` | `make_shared<T>()` | make 更高效（一次分配） |
| **weak\_ptr** | 不能直接构造 | 由 shared\_ptr 推导 | 观察者 |

---

### 5. **`new` 与 `shared_ptr` 的特殊关系**

`shared_ptr` 和 `make_shared` 在内存分配上有重要区别：

cpp

```cpp
// 方式1：直接 new（两次内存分配）
std::shared_ptr<Widget> ptr(new Widget());
// 分配1：Widget 对象
// 分配2：控制块（引用计数、弱引用计数等）

// 方式2：make_shared（一次内存分配）
auto ptr = std::make_shared<Widget>();
// 一次分配：Widget 对象 + 控制块连续存储
// 性能更好，缓存更友好
```

**但是**，`make_shared` 也有缺点：

-
控制块和对象一起分配，即使 weak\_ptr 存在，对象内存也不能释放（因为控制块还在）
-
不能自定义删除器
-
不能使用不完整类型

---

### 6. **裸指针使用规则**

即使有了智能指针，裸指针仍然有用途：

#### 6.1 观察者指针（非拥有）

cpp

```cpp
auto ptr = std::make_unique<Widget>();
Widget* observer = ptr.get();  // ✅ 只观察，不拥有
// 不要 delete observer！
```

#### 6.2 函数参数传递

cpp

```cpp
void process(Widget* widget) {  // 接受裸指针，表示借用
if (widget) widget->doSomething();
}

auto ptr = std::make_unique<Widget>();
process(ptr.get());  // ✅ 传入裸指针
```

#### 6.3 所有权转移

cpp

```cpp
std::unique_ptr<Widget> ptr1 = std::make_unique<Widget>();
std::unique_ptr<Widget> ptr2 = std::move(ptr1);  // ✅ 转移所有权
// ptr1 现在为空
```

---

### 7. **总结对比表**

| 特性 | 裸指针 \+ `new` | `unique_ptr` | `shared_ptr` | `make_*` |
| --- | --- | --- | --- | --- |
| **自动释放** | ❌ 手动 delete | ✅ | ✅ | ✅ |
| **异常安全** | ❌ 危险 | ✅ | ✅ | ✅ |
| **所有权明确** | ❌ 不明确 | ✅ 独占 | ✅ 共享 | ✅ |
| **性能开销** | 最小 | 最小 | 有（引用计数） | 最小 |
| **使用建议** | **❌ 避免** | 默认选择 | 需要共享时 | 优先使用 |

---

### 核心原则

> **1. 永远不要直接使用 `new` 和 `delete`**
> **2. 优先使用 `make_unique` 和 `make_shared`**
> **3. 裸指针只作为观察者，不持有所有权**
> **4. 智能指针是资源管理工具，不是万能替代品**
