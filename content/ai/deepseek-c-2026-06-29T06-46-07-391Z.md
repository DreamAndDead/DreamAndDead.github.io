crtdbg.h

## Assistant

`crtdbg.h` 是 Windows 平台下 Visual Studio C/C\+\+ 开发中一个非常强大的**调试专用头文件**。它的核心作用是帮助你**检测和定位内存泄漏**，是 C/C\+\+ 开发者排查内存问题的利器。

### 核心功能：检测内存泄漏

`crtdbg.h` 提供了 CRT 调试堆函数，能让你在程序的调试版本（Debug）中，追踪内存的分配和释放情况。

---

### 如何使用

在程序源代码中，按以下**固定顺序**包含头文件，即可启用调试堆功能[-3](https://www.pconline.com.cn/pcedu/empolder/gj/vc/0506/648575.html)：

cpp

```cpp
#define _CRTDBG_MAP_ALLOC  // 可选，但建议加上，以获得更详细的信息（如文件名和行号）
#include <stdlib.h>
#include <crtdbg.h>
```

-
`#define _CRTDBG_MAP_ALLOC`：将 CRT 堆函数的基础版本映射到其对应的调试版本，这能让你在泄漏报告中看到具体的文件名和行号。
-
`#include <crtdbg.h>`：这个头文件将 `malloc` 和 `free` 等函数映射到它们的调试版本 `_malloc_dbg` 和 `_free_dbg`，以追踪内存操作。

---

### 如何获取内存泄漏报告

启用之后，主要有两种方式让程序在退出时自动输出内存泄漏报告：

**方式一：在程序退出点调用 `_CrtDumpMemoryLeaks()`**

cpp

```cpp
_CrtDumpMemoryLeaks();
```

**方式二：在程序开始处设置调试标志（推荐）**
如果程序有多个退出点，手动调用 `_CrtDumpMemoryLeaks` 会很麻烦。更好的方法是在程序开头用 `_CrtSetDbgFlag` 设置标志，这样程序在任何出口都会自动报告。

cpp

```cpp
_CrtSetDbgFlag(_CRTDBG_ALLOC_MEM_DF | _CRTDBG_LEAK_CHECK_DF);
```

---

### 解读内存泄漏报告

运行程序后，泄漏信息会输出到 Visual Studio 的“输出”窗口的“调试”窗格中。

-
**如果定义了 `_CRTDBG_MAP_ALLOC`**，报告会非常清晰，直接告诉你泄漏发生在**哪个文件的哪一行**。
text

```text
Detected memory leaks!
Dumping objects ->
c:\users\...\leaktest.cpp(20) : {18} normal block at 0x00780E80, 64 bytes long.
Data: <                > CD CD CD CD CD CD CD CD CD CD CD CD CD CD CD CD
Object dump complete.
```
这里的 `leaktest.cpp(20)` 就指明了泄漏发生在源文件的第 20 行。
-
**如果没有定义 `_CRTDBG_MAP_ALLOC`**，报告信息会相对简略，只显示内存块编号、类型、地址和大小，缺少文件名和行号信息。

---

### 更高级的用法

1.
**区分内存块类型**：调试堆中的内存块分为多种类型，最常见的是 `_NORMAL_BLOCK`（普通块，由你的代码分配）、`_CLIENT_BLOCK`（客户端块，MFC 等库使用）和 `_CRT_BLOCK`（CRT 库内部使用）。你可以在报告中看到这些类型，方便你定位问题根源。
2.
**在特定的内存分配编号上设置断点**：报告中的 `{18}` 表示这是程序运行过程中的第 18 次内存分配。你可以在“监视”窗口中设置 `_crtBreakAlloc = 18`，程序会在第 18 次分配发生时自动中断，方便你检查调用堆栈，了解分配发生在哪里。

### 总结

`crtdbg.h` 是 Windows 下 C/C\+\+ 开发中排查内存泄漏问题的标准工具。通过简单的宏定义和函数调用，你就能获得详细的内存泄漏报告，快速定位问题代码，是 Debug 阶段的必备利器。
