# 核心一句话回答

**我们永远只在【上一个逻辑状态 prev】和【刚算完的当前逻辑状态 curr】之间插值，并不会等待还没计算的「下一个未来逻辑帧」。**
`alpha` 代表：**当前实时时间，距离本次逻辑帧结束已经走了百分之多少**，用来在**已经存在的两个旧结果之间算中间画面**，完全不需要未来的数据。

## 一、先把两套数据存死：永远保存两份逻辑状态

角色必须同时存两套坐标（旋转、缩放同理）：

1. `prevPos`：**上一次逻辑 Tick 结束时的位置（旧状态）**
2. `currPos`：**刚刚本轮 FixedUpdate 算完的最新逻辑位置（新状态）**

逻辑 Tick 执行规则：
 执行一次 FixedUpdate 之前，先把 `currPos` 拷贝进 `prevPos` 存档，再计算出新的 `currPos`。

> 举例：逻辑 60Hz，固定步 `fixedDT = 1/60 ≈ 0.01667s`
>  Tick N 结束：prev = 位置 A，curr = 位置 B
>  Tick N+1 结束：prev = 位置 B，curr = 位置 C

两个点是**百分百已经算好的历史数据**，全程可用。

## 二、alpha 到底是什么？剩余余数的占比

完整主循环流程：

1. 本帧拿到可变渲染总耗时 `deltaTime`，加到时间累加器 `accumulator`
2. 循环执行 FixedUpdate，只要 `accumulator >= fixedDT` 就跑一次逻辑，并且 `accumulator -= fixedDT`
3. 循环结束后，`accumulator` 一定是 **0 ≤ 余数 < fixedDT**（不够再跑一次逻辑的剩余时间）
4. 计算插值系数：$alpha = \frac{accumulator}{fixedDT}$`alpha ∈ [0, 1)`

### alpha 的通俗含义

- alpha = 0：刚跑完一次逻辑，时间刚好卡在逻辑节点起点
- alpha = 0.5：刚好走完本次逻辑间隔一半的时间
- alpha = 0.9：距离下一次逻辑 Tick 只剩 10% 的时间

它描述的是：**现在的实时时间，处在【prev 逻辑帧】和【curr 逻辑帧】区间的什么进度**。

## 三、插值公式：在两个现成状态之间算画面位置

渲染坐标 = 线性插值 Lerp (prev, curr, alpha)

```cpp
renderPos = prevPos + (currPos - prevPos) * alpha;
```

### 举实例一目了然

逻辑 60Hz (16.67ms 一逻辑帧)，显卡 120Hz 渲染，一帧渲染耗时≈8.33ms：

1. 第一轮渲染帧： accumulator = 8.33ms，不足 16.67ms，不执行逻辑 alpha = 8.33 / 16.67 = 0.5 画面绘制在 prev ~ curr 的中点
2. 第二轮渲染帧： 累加后 accumulator = 16.66ms，刚好够一次 fixedDT 执行 FixedUpdate：prev 变成旧 curr，算出全新 curr，accumulator 清零 alpha=0，画面直接渲染最新 curr 坐标

**全程没有用到下一帧还未计算的逻辑位置**，只靠两个已经运算完成的前后逻辑点位，算出中间所有高刷渲染帧的画面。

## 四、解答你的核心疑问：下一个逻辑位置还没出来，怎么插值？

1. **我们插值的区间是「上一逻辑帧 → 当前逻辑帧」，不是「当前→下一逻辑帧」** 下一次逻辑计算本来就还没到时间，我们根本不需要它。我们只是在**上一轮和本轮的结果之间做平滑过渡**，完美填满两次逻辑更新之间的渲染空档。
2. 视觉本质：**画面是对逻辑运动的平滑拟合，不是超前预测未来逻辑结果** 逻辑的运动是匀速的，我们假设两个逻辑点之间物体匀速运动，用线性插值模拟中间路径，视觉完全顺滑。
3. 轻微的微小滞后可以忽略 画面会极小幅滞后逻辑真实时间（最多一个 fixedDT），人眼完全无法察觉； 而换来的是**物理绝对稳定、联机百分百同步、不会帧率越高速度越快**，收益远大于这点微乎其微的视觉延迟。

## 五、对比两种思路，为什么不用预测下一帧？

1. 方案 A（行业标准，当前方案）：插值 **prev ↔ curr**（两个已完成状态） ✅ 数据 100% 确定，无预测误差，物理、碰撞、联机完全稳定，永远不会出错。
2. 方案 B（预测下一帧 curr_next）：靠速度预判未来逻辑位置 ❌ 一旦中途按键转向、碰撞、受力变化，预测直接失效，画面会出现明显回弹、抖动，物理判定和画面错位，联机同步直接崩盘。

## 六、极简时序时间线演示（逻辑 60Hz，渲染 120Hz）

时间轴：t0 (逻辑 N) → t1 (渲染 1) → t2 (渲染 2 = 逻辑 N+1)

- t0：逻辑运算完成，prev=P0，curr=P1
- t1（中间渲染帧）：alpha=0.5，渲染画面 = Lerp (P0,P1,0.5)
- t2：时间抵达逻辑节点，执行新逻辑，prev=P1，curr=P2，alpha 归零，渲染 P2

两次逻辑中间多出的渲染帧，全部靠**已有的 P0、P1**插值补齐，全程不需要未来的 P2。

## 七、补充拓展：什么情况才用外推（预测下一位置）？

只有**网络联机客户端本地预判移动**才会用速度外推下一帧位置，而且**只用于画面显示**；
 最终的逻辑、碰撞、伤害判定，依旧以服务器下发的固定逻辑帧为准，本地预测只是优化手感，不会改动核心逻辑。

## 总结

1. Alpha 用的是**本次逻辑间隔的剩余时间占比**，只作用于**上一次逻辑状态 和 当前最新逻辑状态**；
2. 高帧率渲染帧，只是在两个现成的逻辑点位之间做线性填充，完全不需要等待还未计算的下一个逻辑帧；
3. 逻辑低频保证稳定，渲染高频插值保证顺滑，二者天然解耦同步。
