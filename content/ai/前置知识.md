先说结论：**标准 OpenGL / GLFW 没有直接一行 API 判断 FreeSync (Adaptive-Sync/VRR) 的接口**。
 程序层面只能做「间接检测」，分两套方案：**OpenGL 扩展查询（标准跨平台）、Windows 系统 API 查询、备选方案运行时试探**，下面给完整可用的 C++ 代码。

# 前置知识

FreeSync 的底层标准名称是 **Adaptive-Sync**，对应 OpenGL 扩展：
`WGL_EXT_swap_control_tear`（Windows OpenGL） / `GLX_EXT_swap_control_tear`（Linux）
 这个扩展存在，代表显卡 + 显示器支持 VRR（FreeSync / G-Sync 兼容）；
 该扩展就是自适应同步的底层依赖。

VSync 普通开关用的是 `WGL_EXT_swap_control`，而 ** tear 扩展才是 VRR 的标识 **。

## 一、Windows + GLFW + OpenGL 判断（最常用）

### 原理

1. 创建 OpenGL 上下文后，查询是否存在扩展 `WGL_EXT_swap_control_tear`
2. 存在 ≈ 硬件支持 Adaptive-Sync（FreeSync/G-Sync 兼容）
3. 不存在 = 纯固定刷新率屏幕，不支持 VRR

完整可运行代码：

```cpp
#include <GLFW/glfw3.h>
#include <cstring>
#include <iostream>

// 判断字符串是否存在于扩展列表
bool ExtensionSupported(const char* extList, const char* extName)
{
    const char* ptr = extList;
    size_t len = strlen(extName);
    while (*ptr)
    {
        size_t curLen = strcspn(ptr, " ");
        if (curLen == len && strncmp(ptr, extName, len) == 0)
            return true;
        ptr += curLen + 1;
    }
    return false;
}

// Windows 判断 WGL 自适应同步扩展
bool IsAdaptiveSyncSupported()
{
#ifdef _WIN32
    const char* wglExts = (const char*)wglGetExtensionsStringARB(wglGetCurrentDC());
    if (!wglExts) return false;
    // 核心扩展：WGL_EXT_swap_control_tear
    return ExtensionSupported(wglExts, "WGL_EXT_swap_control_tear");
#elif __linux__
    // Linux GLX 对应 GLX_EXT_swap_control_tear
    const char* glxExts = glXQueryExtensionsString(glXGetCurrentDisplay(), 0);
    return ExtensionSupported(glxExts, "GLX_EXT_swap_control_tear");
#endif
}

int main()
{
    glfwInit();
    GLFWwindow* win = glfwCreateWindow(800, 600, "Check FreeSync", nullptr, nullptr);
    glfwMakeContextCurrent(win);

    bool supportVRR = IsAdaptiveSyncSupported();
    if (supportVRR)
    {
        std::cout << "当前硬件支持 Adaptive-Sync(FreeSync/G-Sync兼容)\n";
        glfwSwapInterval(0); // 关闭VSync，启用自适应同步
    }
    else
    {
        std::cout << "不支持VRR自适应同步，可开启普通VSync防撕裂\n";
        glfwSwapInterval(1);
    }

    while (!glfwWindowShouldClose(win))
    {
        glClear(GL_COLOR_BUFFER_BIT);
        glfwSwapBuffers(win);
        glfwPollEvents();
    }

    glfwDestroyWindow(win);
    glfwTerminate();
    return 0;
}
```

## 二、关键补充说明

1. **扩展存在 ≠ 当前已经成功开启 FreeSync** 扩展只是**硬件具备能力**，真正生效还要满足：

- 线材为 DP 1.2a / HDMI2.1
- 显示器 OSD 菜单手动打开 FreeSync
- N 卡需在控制面板开启 G-Sync 兼容，A 卡开启 FreeSync 程序只能查能力，无法直接读取显示器 OSD 开关状态。

2. 窗口模式限制 大部分桌面系统，**无边框全屏 / 独占全屏**才能完整启用 VRR；普通窗口模式下，VRR 经常被桌面合成器（Windows DWM）强制禁用，即便扩展检测成功，运行也不会生效。

## 三、DirectX 环境判断（DX11/DX12）

DX 可以通过 `IDXGIOutput::GetDesc1()` 读取显示器刷新率模式，查看是否包含**可变刷新率范围**，可以精准拿到 VRR 区间，游戏引擎 DX 后端常用。
 核心字段：`DXGI_MODE_DESC1` 的刷新率支持区间非单一固定值，即判定支持 FreeSync。

## 四、无法通过 OpenGL 直接读取的信息

1. 不能区分是 FreeSync (AMD) 还是 G-Sync (N 卡兼容)，二者底层都是 Adaptive-Sync，程序层面完全一致；
2. 拿不到显示器当前 FreeSync 的开关状态，只能靠用户手动在显示器、显卡驱动开启；
3. 无法读取 VRR 最低 / 最高刷新率区间，需要 DX 或者读取显示器 EDID 信息才能解析。

## 五、兜底运行时试探方案（简易判断是否真的在生效）

如果检测扩展为 true，依然不确定是否生效，可以逻辑测速：
 关闭 VSync，把渲染帧率上限锁在显示器刷新率中间值（比如 144Hz 屏锁 100 帧）。

- 帧率稳定卡在 100 左右，画面无撕裂 → FreeSync 正常生效
- 帧率跑满 144 上限、画面明显撕裂 → VRR 未成功开启。

## 六、对应你游戏开发的业务用法

```cpp
// 伪代码主逻辑
bool hasVRR = IsAdaptiveSyncSupported();
if(hasVRR)
{
    glfwSwapInterval(0);        // 关闭VSync
    SetTargetFPS(monitorMaxHz - 4); // 帧率上限略低于最大刷新率
}
else
{
    glfwSwapInterval(1);        // 无VRR，开启VSync防撕裂
}
```

## 总结

1. OpenGL 核心检测依据：`WGL_EXT_swap_control_tear` 扩展是否存在，存在即硬件支持 FreeSync/Adaptive-Sync；
2. 程序只能检测硬件能力，**不能读取显示器的 FreeSync 开关**，开关需要用户外设端手动开启；
3. 检测成功后代码务必关闭`SwapInterval(0)`，配合帧率上限，自适应同步才能正常工作。
