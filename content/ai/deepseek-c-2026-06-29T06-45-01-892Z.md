## C\+\+ 访问修饰符：public vs protected

这是 C\+\+ 面向对象设计中**封装性**的核心问题。它们的核心区别决定了**谁能访问**类的成员。

---

### 快速对比表

| 访问级别 | 类内部 | 派生类内部 | 类外部（对象） | 友元 |
| --- | --- | --- | --- | --- |
| **public** | ✅ | ✅ | ✅ | ✅ |
| **protected** | ✅ | ✅ | ❌ | ✅ |
| **private** | ✅ | ❌ | ❌ | ✅ |

---

### 1. **public：接口（Interface）**

`public` 成员是类的**对外接口**，任何地方都可以访问。

#### 适用场景：

-
**类的核心功能**：对外提供的服务
-
**构造函数/析构函数**：用于创建和销毁对象
-
**对外暴露的行为**：用户需要调用的方法

cpp

```cpp
class Calculator {
public:
Calculator() : result(0) {}  // 构造函数
void add(int x) { result += x; }   // ✅ 用户需要调用的方法
int getResult() const { return result; }  // ✅ 获取数据的方法

private:
int result;  // 数据隐藏在 private
};

// 使用：
Calculator calc;
calc.add(5);        // ✅ public，可以调用
int res = calc.getResult();  // ✅ public，可以调用
```

**设计原则：** 把"用户需要做什么"暴露为 public，把"怎么做"隐藏起来。

---

### 2. **protected：给派生类用的接口**

`protected` 成员是**给派生类使用的**，但对外部世界隐藏。

#### 适用场景：

-
**基类的内部实现细节**：派生类需要重写或使用
-
**派生类需要访问的成员变量**：但不想暴露给外部
-
**框架设计中的钩子（Hook）**：派生类可以重写的扩展点

cpp

```cpp
class Animal {
public:
virtual ~Animal() = default;
void speak() {
// 公共接口
makeSound();  // 调用 protected 方法
}

protected:
int age = 0;
virtual void makeSound() {  // ✅ 派生类可以重写
std::cout << "Some sound\n";
}

void setAge(int a) { age = a; }  // ✅ 派生类可以调用
};

class Dog : public Animal {
public:
// 重写基类的 protected 方法
void makeSound() override {  // ✅ 可以访问 protected 成员
setAge(5);  // ✅ 调用 protected 方法
std::cout << "Woof! (age: " << age << ")\n";  // ✅ 访问 protected 变量
}
};

// 使用：
Animal* a = new Dog();
a->speak();  // ✅ public 可以调用
// a->makeSound();  // ❌ 错误！protected，外部不能调用
// a->age = 10;     // ❌ 错误！protected，外部不能访问
```

### 3. **典型设计模式中的使用**

#### 模板方法模式（Template Method）

cpp

```cpp
class Game {
public:
// 公共接口，定义了算法骨架
void play() {
initialize();   // protected
startGame();    // protected，派生类实现
endGame();      // protected，派生类实现
}

protected:
virtual void initialize() { /* 默认实现 */ }
virtual void startGame() = 0;  // 纯虚函数，派生类必须实现
virtual void endGame() = 0;
};

class Chess : public Game {
protected:
void startGame() override { /* 下棋逻辑 */ }
void endGame() override { /* 结束逻辑 */ }
};

// 使用：
Chess chess;
chess.play();  // ✅ public 接口
```

### 4. **选择指南：public vs protected**

| 使用场景 | 选择 | 原因 |
| --- | --- | --- |
| **构造函数/析构函数** | `public` | 外部需要创建对象 |
| **用户调用的主要功能** | `public` | 对外暴露的接口 |
| **派生类需要扩展的方法** | `protected` | 只给子类用，隐藏实现 |
| **派生类需要访问的数据** | `protected` | 避免外部直接修改 |
| **内部辅助函数** | `private` | 不希望任何外部看到 |
| **纯虚函数** | `protected` 或 `public` | 看是否需要外部调用 |

---

### 5. **重要设计原则**

#### 原则 1：默认使用 private

除非有明确理由，否则成员变量应该用 `private`。

cpp

```cpp
class Employee {
public:
// 通过 public 方法访问 private 数据
void setSalary(int s) {
if (s >= 0) salary = s;  // 可以加入验证逻辑
}
int getSalary() const { return salary; }

private:
int salary;  // ✅ private，外部不能直接修改
};
```

#### 原则 2：protected 不是"更开放的 private"

很多人把 `protected` 当作 `private` 的放宽版本，但这会破坏封装。

cpp

```cpp
class Base {
protected:
int data;  // ⚠️ 派生类可以直接修改，可能导致耦合
};

class Derived : public Base {
void func() {
data = 100;  // 直接修改基类内部状态，危险！
}
};
```

**更好的方式：** 提供 protected 方法而不是直接暴露成员变量。

cpp

```cpp
class Base {
private:
int data;

protected:
void setData(int val) {
// 可以加入验证和日志
if (val > 0) data = val;
}
};
```

### 6. **特殊场景：protected 构造函数**

`protected` 构造函数用于**抽象类**或**不允许直接实例化的类**。

cpp

```cpp
class Base {
protected:
Base() {}  // 不能直接实例化

public:
virtual ~Base() = default;
};

class Derived : public Base {
public:
Derived() : Base() {}  // ✅ 派生类可以调用
};

// Base b;      // ❌ 错误！protected 构造函数
Derived d;      // ✅ 可以
```

### 7. **访问修饰符的继承规则**

| 派生方式 | public 继承 | protected 继承 | private 继承 |
| --- | --- | --- | --- |
| **基类 public** | 派生类 public | 派生类 protected | 派生类 private |
| **基类 protected** | 派生类 protected | 派生类 protected | 派生类 private |
| **基类 private** | 不可访问 | 不可访问 | 不可访问 |

cpp

```cpp
class Base {
public:
int pub;
protected:
int prot;
private:
int priv;
};

class DerivedPublic : public Base {
// pub 变成 public
// prot 变成 protected
// priv 不可访问
};

class DerivedProtected : protected Base {
// pub 变成 protected
// prot 变成 protected
// priv 不可访问
};

class DerivedPrivate : private Base {
// pub 变成 private
// prot 变成 private
// priv 不可访问
};
```

### 核心记忆

> **public = 给用户看（接口）**
> **protected = 给子类看（扩展点）**
> **private = 自己看（实现细节）**

**一句话规则：**

-
别人要用 → **public**
-
派生类要用 → **protected**
-
只有自己用 → **private**
