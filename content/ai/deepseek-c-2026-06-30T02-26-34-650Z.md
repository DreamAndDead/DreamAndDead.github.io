## `dynamic_cast` 的 RTTI 实现原理

`dynamic_cast` 是 C\+\+ 中唯一一个**运行时**进行类型检查的转换操作符，它的实现依赖于 **RTTI（Run-Time Type Information，运行时类型信息）**。理解其原理，能帮你更好地理解多态的成本和限制。

---

### 1. **RTTI 基础**

RTTI 是 C\+\+ 提供的运行时类型识别机制，主要包含：

-
**`typeid` 操作符**：获取类型信息
-
**`dynamic_cast` 操作符**：安全的类型转换

#### 1.1 RTTI 的启用条件

cpp

```cpp
class Base {
virtual ~Base() = default;  // ✅ 必须有虚函数，RTTI 才能工作
};

class Derived : public Base {};

// 使用 RTTI
Base* ptr = new Derived();
if (typeid(*ptr) == typeid(Derived)) {  // ✅ 可以
std::cout << "ptr 指向 Derived\n";
}

class NoVirtual {};  // ❌ 没有虚函数
NoVirtual* nv = new NoVirtual();
// typeid(*nv);  // 编译错误！没有虚函数，RTTI 不可用
```

---

### 2. **RTTI 的数据结构**

每个含有虚函数的类，编译器都会生成**两个关键数据结构**：

#### 2.1 虚函数表（vtable）

每个类有一个虚函数表，存储所有虚函数的地址。

#### 2.2 类型信息结构（type\_info）

每个类有一个 `std::type_info` 对象，存储类的名称、继承关系等信息。

**内存布局示意：**

text

```text
对象内存布局：
+------------------+
| vptr (虚指针)    | ---> 指向 vtable
+------------------+
| 成员变量         |
+------------------+

vtable 布局：
+------------------+
| offset_to_top    |  指向对象起始位置的偏移
+------------------+
| type_info*       |  ---> 指向 std::type_info 对象
+------------------+
| Base::func1()    |  虚函数地址
+------------------+
| Base::func2()    |
+------------------+
| ...              |
+------------------+
```

---

### 3. **`dynamic_cast` 的实现流程**

`dynamic_cast` 的核心是**遍历继承树**，检查目标类型是否在对象的继承链中。

#### 3.1 向上转换（派生类→基类）

最简单，无需 RTTI，编译时就能确定。

cpp

```cpp
Derived d;
Base* b = dynamic_cast<Base*>(&d);  // 和 static_cast 一样，编译时确定
```

#### 3.2 向下转换（基类→派生类）

需要运行时检查：

cpp

```cpp
Base* ptr = getSomeObject();  // 运行时才知道真正类型
Derived* d = dynamic_cast<Derived*>(ptr);
```

**实现伪代码：**

cpp

```cpp
// dynamic_cast<T*>(ptr) 的简化实现
T* dynamic_cast_impl(void* ptr) {
if (ptr == nullptr) return nullptr;

// 1. 通过 vptr 获取 vtable
void** vptr = *(void***)ptr;

// 2. 从 vtable 中获取 type_info
std::type_info* actual_type = (std::type_info*)vptr[-1];  // 通常在 vtable 的偏移 -1 位置

// 3. 检查 actual_type 是否继承自 T
if (is_base_of(T, actual_type)) {
// 4. 计算偏移量，调整指针（处理多重继承）
return adjust_pointer(ptr, offset);
}

return nullptr;  // 转换失败
}
```

### 4. **多重继承下的 `dynamic_cast`**

在多重继承下，`dynamic_cast` 需要处理**指针调整**问题。

cpp

```cpp
class Base1 { virtual ~Base1() = default; };
class Base2 { virtual ~Base2() = default; };
class Derived : public Base1, public Base2 {};

Base2* ptr = new Derived();  // ptr 指向 Derived 的 Base2 子对象
Derived* d = dynamic_cast<Derived*>(ptr);  // 需要调整指针！
```

**内存布局：**

text

```text
Derived 对象：
+------------------+
| Base1 子对象     |  (vptr 指向 Base1 的 vtable)
|   +------------+ |
|   | vptr       | |
|   +------------+ |
|   | 成员变量   | |
+------------------+
| Base2 子对象     |  (vptr 指向 Base2 的 vtable)
|   +------------+ |
|   | vptr       | |
|   +------------+ |
|   | 成员变量   | |
+------------------+
| Derived 成员     |
+------------------+
```

**`dynamic_cast` 如何处理：**

1.
检查 `ptr` 实际指向 `Derived` 对象
2.
计算 `Base2` 子对象到 `Derived` 对象起始位置的偏移量
3.
调整指针：`char* adjusted = (char*)ptr - offset`
4.
返回调整后的指针

**vtable 中的偏移信息：**

text

```text
Base2 的 vtable：
+------------------+
| offset_to_top    |  = -sizeof(Base1)  (指向 Derived 起始位置的偏移)
+------------------+
| type_info*       |  指向 Derived 的 type_info
+------------------+
| Base2::func1()   |
+------------------+
| ...              |
+------------------+
```

### 5. **`typeid` 的实现**

`typeid` 用于获取对象的类型信息：

cpp

```cpp
Base* ptr = new Derived();
const std::type_info& info = typeid(*ptr);
std::cout << info.name();  // 输出 "Derived"
```

**实现原理：**

1.
通过对象的 `vptr` 找到 `vtable`
2.
从 `vtable` 中提取 `type_info*` 指针
3.
返回 `type_info` 引用

---

### 6. **RTTI 的开销**

| 开销类型 | 说明 | 影响 |
| --- | --- | --- |
| **内存开销** | 每个多态类增加一个 vtable | 包含 type\_info 指针和偏移信息 |
| **时间开销** | `dynamic_cast` 需要遍历继承树 | O\(n\)，n 为继承链深度 |
| **代码膨胀** | 编译器生成类型比较代码 | 增加二进制大小 |

**性能测试示例：**

cpp

```cpp
#include <chrono>

class Base { virtual ~Base() = default; };
class Derived : public Base {};

void test() {
Base* ptr = new Derived();
auto start = std::chrono::high_resolution_clock::now();

for (int i = 0; i < 1'000'000; ++i) {
Derived* d = dynamic_cast<Derived*>(ptr);
}

auto end = std::chrono::high_resolution_clock::now();
// dynamic_cast 比 static_cast 慢几倍到几十倍
}
```

### 7. **RTTI 的禁用**

如果不需要 RTTI，可以通过编译器选项禁用：

-
**MSVC**: `/GR-` \(默认启用 `/GR`\)
-
**GCC/Clang**: `-fno-rtti`

禁用后：

-
`typeid` 和 `dynamic_cast` 对多态类型不可用
-
可减小二进制大小，提升性能（嵌入式系统常用）

cpp

```cpp
// 编译时使用 -fno-rtti
class Base { virtual ~Base() = default; };
Base* ptr = new Base();
// typeid(*ptr);  // ❌ 编译错误：RTTI 被禁用
// dynamic_cast<Derived*>(ptr);  // ❌ 编译错误
```

### 8. **实现细节：MSVC vs GCC**

不同编译器的实现略有差异：

#### MSVC \(Microsoft Visual C\+\+\)

-
vtable 布局：`{ type_info*, offset_to_top, virtual_function_pointers... }`
-
`type_info*` 在 vtable 的第一个位置

#### GCC/Clang \(Itanium ABI\)

-
vtable 布局：`{ offset_to_top, type_info*, virtual_function_pointers... }`
-
`type_info*` 在 vtable 的第二个位置

**MSVC 的 vtable 布局：**

text

```text
+------------------+
| type_info*       |  <-- 偏移 0
+------------------+
| offset_to_top    |  <-- 偏移 sizeof(type_info*)
+------------------+
| virtual_function |
+------------------+
```

**GCC 的 vtable 布局：**

text

```text
+------------------+
| offset_to_top    |  <-- 偏移 0
+------------------+
| type_info*       |  <-- 偏移 sizeof(void*)
+------------------+
| virtual_function |
+------------------+
```

### 9. **`dynamic_cast` 的限制**

| 限制 | 说明 |
| --- | --- |
| **必须有虚函数** | 类必须有多态性（至少一个虚函数） |
| **只能用于公共继承** | `private`/`protected` 继承不支持 |
| **性能开销** | 运行时检查，有性能损耗 |
| **RTTI 必须启用** | 编译时不能禁用 RTTI |
| **不能用于非多态类型** | `dynamic_cast<int*>` 无效 |

cpp

```cpp
class Base1 { virtual ~Base1() = default; };
class Base2 {};
class Derived : public Base1, public Base2 {};  // Base2 不是多态的

Derived d;
Base1* b1 = &d;
Base2* b2 = &d;

// dynamic_cast<Base2*>(b1);  // ❌ 编译错误！Base2 没有虚函数
// static_cast<Base2*>(b1);   // ✅ 编译通过，但不安全
```

### 总结

**核心要点：**

1.
`dynamic_cast` 依赖 **RTTI**，只有多态类型（有虚函数）才能使用
2.
**vtable 中存储了 `type_info`** 和 **偏移信息**，用于运行时类型检查和指针调整
3.
**多重继承**下需要进行指针偏移调整，这增加了复杂性
4.
RTTI 有**内存和时间开销**，嵌入式或性能敏感场景可以禁用
5.
`dynamic_cast` 是唯一能在运行时安全进行向下转换的工具

**记忆口诀：**

> **动态转换靠 RTTI，虚表里面藏秘密**
> **类型信息存指针，继承遍历求结果**
> **多重继承要调偏，成功返回失败空**
> **开销虽大但安全，多态世界离不开**
