如何节省token？

## Assistant

在 OpenCode 中节省 Token，核心思路就是**"少说废话，精准投喂"**。我按效果从高到低给你几个实用技巧：

---

## 1️⃣ 先用 Plan 模式，再用 Build 模式（最重要）

这是**最省钱**的技巧。Plan 模式只读不写，消耗的 Token 远低于 Build 模式，因为它不需要反复读取上下文和文件内容。

-
  **错误做法**：直接进 Build 模式说"重构整个模块"，AI 会一次性读大量文件，Token 直接爆表。
-
  **正确做法**：先 `/plan` 让 AI 出方案，你确认后，再用 Build 模式执行。方案确认后，执行阶段 AI 可以只聚焦在改动点上，不用反复扫全盘。

**省Token估算**：复杂任务可省 **50%~70%**。

---

## 2️⃣ 明确目标，避免"边聊边改"

每多一轮对话，AI 都要重新加载之前的对话历史，历史越长，Token 消耗越大。

-
  **坏例子**："帮我改个函数" → AI 改完 → "再加个日志" → AI 再改 → "不对，改成这样"...
-
  **好例子**："帮我修改 `utils.js` 中的 `formatDate` 函数，添加时区支持，同时在该函数内增加错误日志记录。"

一次性说清楚，把多个要求合并成一条指令，能大幅减少往返轮次。

---

## 3️⃣ 用 `/new` 清空历史，不要用 `/exit` 重开

如果上一轮对话已经完成，但你要开启**全新的、无关的任务**，直接用 `/new` 清空会话。

-
  `/new`：清空历史但**保留程序运行**，Token 不累积。
-
  `/exit`：退出程序，下次重新启动时会重新加载环境，反而可能触发更多的初始化读取。

**记住**：无关任务不要接着聊，历史对话越长，每次请求的上下文成本越高。

---

## 4️⃣ 手动"修剪"上下文

OpenCode 会自动把相关文件读进上下文，但有时它会"过度读取"。

-
  **主动控制范围**：在指令中明确说明"只关注 `src/controller/` 目录下的文件"。
-
  **排除无关文件**：用 `.opencodeignore` 文件排除日志、构建产物、测试报告等大文件，避免被 AI 误读。

---

## 5️⃣ 用 `@` 引用，精准投喂

不要让它自己去猜，直接用 `@文件名` 或 `@目录` 告诉它重点关注什么。

-
  **模糊**："帮我看看登录模块有什么问题" → AI 可能要扫描整个项目找"登录"相关。
-
  **精准**："帮我看看 `@src/auth/login.js` 中 JWT 过期处理有什么问题" → 只读这一个文件。

---

## 6️⃣ 设置 Token 预算上限（硬性控制）

OpenCode 支持在配置中设置单次请求的 Token 上限：

json

```json
// ~/.opencode/config.json
{
  "maxTokens": 4000  // 根据任务复杂度调整，默认可能较高
}
```

设置后，AI 会自动限制输出长度，避免它"长篇大论"。
