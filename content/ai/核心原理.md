下面分 **Raylib、SFML、GLFW (原生 OpenGL)** 三种最常用 C++ 游戏框架，分别给出**锁定渲染帧率上限**的标准写法，顺带讲原理、优缺点、和 V-Sync 垂直同步的区别。

# 核心原理

锁定帧率上限 = 限制**渲染循环每秒最多执行多少次**，本质是：
 每帧渲染结束后，主动休眠一小段时间，把帧间隔拉长，强制最高 FPS。
 分两种实现：

1. **框架自带函数（最简单）**
2. **手动时间休眠控制（底层通用）**

## 一、Raylib（最简单，一行代码）

函数：`SetTargetFPS(int maxFps)`
 放在窗口初始化之后即可全局锁上限。

```cpp
#include <raylib.h>

int main()
{
    InitWindow(800, 600, "Lock FPS");
    SetTargetFPS(144);   // 锁定渲染上限144帧
    // SetTargetFPS(60); // 锁60帧

    while (!WindowShouldClose())
    {
        float deltaTime = GetFrameTime(); // dt依然自动适配锁定后的帧间隔
        BeginDrawing();
        ClearBackground(WHITE);
        DrawText(TextFormat("FPS: %.1f", GetFPS()), 10,10,20,BLACK);
        EndDrawing();
    }
    CloseWindow();
    return 0;
}
```

内部实现：每帧末尾自动 Sleep 补齐时间，限制循环频率。

## 二、SFML 锁定帧率上限

### 方式 1：setFramerateLimit () 原生接口

```cpp
#include <SFML/Graphics.hpp>

int main()
{
    sf::RenderWindow window(sf::VideoMode(800,600), "SFML FPS Limit");
    window.setFramerateLimit(120); // 渲染上限120FPS

    sf::Clock clock;
    while(window.isOpen())
    {
        float dt = clock.restart().asSeconds();
        window.clear(sf::Color::White);
        window.display();
    }
    return 0;
}
```

### 方式 2：开启垂直同步（VSync）

```cpp
window.setVerticalSyncEnabled(true);
```

VSync 会强制帧率**对齐显示器刷新率**（60/144Hz），优先级高于帧率上限。

## 三、底层 GLFW + OpenGL 原生手写（无封装，手动锁上限）

框架没有内置限帧函数，自己用时间计算休眠，逻辑通用所有底层 API。
 思路：
 记录上一帧结束时间，当前帧耗时不足目标帧间隔，则休眠差值时间。

```cpp
#include <GLFW/glfw3.h>
#include <thread>
#include <chrono>

// 锁定上限FPS
const int MAX_FPS = 120;
const double FRAME_TIME = 1.0 / MAX_FPS; // 单帧目标间隔秒数

int main()
{
    glfwInit();
    GLFWwindow* win = glfwCreateWindow(800,600,"GLFW Limit FPS",nullptr,nullptr);
    glfwMakeContextCurrent(win);

    double lastTime = glfwGetTime();

    while (!glfwWindowShouldClose(win))
    {
        double currentTime = glfwGetTime();
        double deltaTime = currentTime - lastTime;

        // ========== 逻辑 + 渲染 ==========
        glClear(GL_COLOR_BUFFER_BIT);
        glfwSwapBuffers(win);
        glfwPollEvents();

        // ========== 手动限帧核心代码 ==========
        double usedTime = glfwGetTime() - lastTime; // 本帧已经消耗的时间
        double sleepTime = FRAME_TIME - usedTime;

        // 还有剩余时间，休眠补齐
        if(sleepTime > 0.0)
        {
            // 高精度休眠
            std::this_thread::sleep_for(std::chrono::duration<double>(sleepTime));
        }

        lastTime = glfwGetTime();
    }
    glfwTerminate();
    return 0;
}
```

## 四、两个关键概念区分（极易搞混）

### 1. 帧率上限 LimitFPS（我们上面写的）

- 人为设置**最高帧数**，比如锁 144，性能够最多跑 144，场景复杂可以自动降到更低。
- 属于**软限制**，底层依然是**可变渲染帧**，`deltaTime` 依旧逐帧计算，只是封顶。
- 不绑定显示器刷新率，可能画面撕裂。

### 2. 垂直同步 VSync

- 强制渲染和显示器刷新时刻完全对齐，FPS 只能等于显示器刷新率 (60/144) 的约数。
- 优点：**杜绝画面撕裂**
- 缺点：固定等待屏幕刷新，会**增加输入延迟**，竞技游戏一般关闭 VSync，只用帧率上限。

### 优先级

开启 VSync > 帧率上限。
 同时开启时，最终帧率以屏幕刷新率为准。

## 五、常见使用建议

1. **单机 3A、日常游玩** 开启 VSync + 适当上限（比如显示器 144Hz，锁 144），防撕裂、控功耗。
2. **竞技游戏、射击 MOBA****关闭 VSync**，只设置帧率上限（比如 240），追求最低输入延迟。
3. **手机移动端** 引擎自带帧率档位（30/60/120），本质就是封装好的渲染上限，用来控温控功耗。

## 六、补充：锁定渲染帧率 完全不影响 FixedUpdate 固定逻辑步

一定要记住：
`SetTargetFPS` / `setFramerateLimit` **只限制渲染循环的执行速度**，
 你的固定物理逻辑 `FixedUpdate(fixedDT)` 是靠时间累加器 `accumulator` 独立驱动的，
 逻辑频率完全不受渲染帧率上限影响，速度、碰撞判定依旧稳定。
 高刷屏锁帧、降帧，角色移动速度永远一致。

## 七、常见小坑

1. Windows 系统休眠精度较低，`std::this_thread::sleep_for` 最小时间粒度大概 1ms，低 FPS 锁帧误差明显，高帧率（120/144）几乎无影响。
2. 不要把**逻辑固定步**和**渲染上限**设成同一个数值，渲染一定要高于逻辑帧率，才能发挥 alpha 插值顺滑画面的作用。 例：逻辑固定 60Hz，渲染上限锁 120/144。
