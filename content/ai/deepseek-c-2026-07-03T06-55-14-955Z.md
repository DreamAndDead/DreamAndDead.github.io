## User

clangd 能否检测出命名规范？

## Assistant

可以。clangd 本身确实**不能**直接检测命名规范，但它内嵌并集成了 `clang-tidy` 的 `readability-identifier-naming` 这项功能[-1](https://clangd.llvm.org/faq)[-2](https://clangd.llvm.org/features)。本质上，你是通过 **clangd 运行 clang-tidy 的这项命名检查**。

这个配置是通过一个名为 `readability-identifier-naming` 的检查实现的[-2](https://clangd.llvm.org/features)[-3](https://clang.llvm.net.cn/extra/clang-tidy/checks/readability/identifier-naming.html)[-7](http://releases-origin.llvm.org/6.0.1/tools/clang/tools/extra/docs/clang-tidy/checks/readability-identifier-naming.html)。你可以通过两种方式配置它，让它按你的要求进行检查，并在代码中给出提示或自动修正建议。

### ⚙️ 核心配置方式

命名规范的检查通过 `readability-identifier-naming` 进行配置，提供两种配置途径：

1.
**项目配置文件 `.clang-tidy`**（推荐）
在项目根目录创建此文件，规则会作为项目约束被统一应用。这是一个非常成熟且广泛使用的方式[-5](https://discourse.bemanproject.org/t/static-analyser-clang-tidy-which-checks-should-be-used/273/2)。
2.
**clangd 的 YAML 配置文件**
在 `clangd` 的配置文件中直接为 `ClangTidy` 部分添加规则[-1](https://clangd.llvm.org/faq)。这种方式更聚焦于 LSP 服务本身的设置。

### 📝 配置示例

下面以 `.clang-tidy` 文件为例，展示如何配置让 clangd 检查 Google 风格命名[-3](https://clang.llvm.net.cn/extra/clang-tidy/checks/readability/identifier-naming.html)[-5](https://discourse.bemanproject.org/t/static-analyser-clang-tidy-which-checks-should-be-used/273/2)：

yaml

```yaml
# .clang-tidy 文件
Checks: 'readability-identifier-naming'
CheckOptions:
# 规定类名必须是大驼峰 (CamelCase)
- key: readability-identifier-naming.ClassCase
value: CamelCase
# 规定函数名必须是小驼峰 (camelBack)
- key: readability-identifier-naming.FunctionCase
value: camelBack
# 规定成员变量名必须是小驼峰，且以下划线结尾
- key: readability-identifier-naming.MemberCase
value: camelBack
- key: readability-identifier-naming.MemberSuffix
value: _
```

> 需要说明的是，`readability-identifier-naming` 检查的启用与配置，在不同版本的 clangd 或不同社区的具体实践细节上可能存在细微差异，建议以你所使用工具的官方文档为准[-5](https://discourse.bemanproject.org/t/static-analyser-clang-tidy-which-checks-should-be-used/273/2)[-7](http://releases-origin.llvm.org/6.0.1/tools/clang/tools/extra/docs/clang-tidy/checks/readability-identifier-naming.html)[-8](https://lists.llvm.org/pipermail/cfe-commits/Week-of-Mon-20211213/396051.html)。

### ✍️ 配置项详解

`readability-identifier-naming` 检查支持对**不同类型**的标识符分别设置规则[-3](https://clang.llvm.net.cn/extra/clang-tidy/checks/readability/identifier-naming.html)。你可以通过配置选项精确控制，例如：

| 配置项 | 说明 | 可选值示例 |
| --- | --- | --- |
| `ClassCase` | 类/结构体名风格 | `CamelCase`, `lower_case`, `UPPER_CASE` |
| `FunctionCase` | 函数名风格 | `camelBack`, `lower_case` |
| `VariableCase` | 普通变量名风格 | `camelBack`, `lower_case` |
| `MemberCase` | 类成员变量名风格 | `camelBack` |
| `MemberPrefix` | 成员变量前缀 | `m_` |
| `MemberSuffix` | 成员变量后缀 | `_` |
| `ConstantCase` | 常量名风格 | `UPPER_CASE` |
| ... | 参数、枚举等 | 类似配置 |

> **注**：完整选项列表很长，你可以在 LLVM 官方文档中查阅所有配置项[-3](https://clang.llvm.net.cn/extra/clang-tidy/checks/readability/identifier-naming.html)。这些命名规则同时也遵循 C/C\+\+ 标准中关于保留标识符的规范，`bugprone-reserved-identifier` 检查会专门标记以下划线和大写字母开头的保留名称，避免未定义行为[-4](https://clang.llvm.net.cn/extra/clang-tidy/checks/bugprone/reserved-identifier.html#cmdoption-arg-AllowedIdentifiers)。
