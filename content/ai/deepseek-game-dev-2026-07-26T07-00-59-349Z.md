你问到了游戏物理引擎最核心的“心脏手术”——**穿透修正（Penetration Correction）**。这不仅是让角色站在地面上的基础，更是处理高速移动、堆叠物体、复杂地形时不发生“爆炸”或“瞬移”的关键。

结合我们之前聊的“始终施加重力”和“ECS架构”，下面我把这个算法的**底层原理**、**数学实现**、**工业级迭代方案**以及**在ECS中的工程落地**彻底讲透。

---

### 1. 为什么必须做穿透修正？

当你让角色移动时（`position += velocity * dt`），由于时间步长（dt）不是无限小，物体会**穿透（Overlap）**到另一个物体内部。如果不修正，下一帧物体会穿透更深，最终穿模掉出世界。

**穿透修正的本质**：在检测到重叠后，**将物体沿最短路径“推”出重叠区域**，并调整速度以防止再次穿透。

---

### 2. 基础版：线性投影法（Linear Projection）

这是最简单的修正方法，适用于**静态地形（如地面、墙壁）**。

**输入**：碰撞检测（如 `SweepTest` 或 `OverlapTest`）返回的：

-
  `hitNormal`（法线）：从地面指向角色的方向（即推开方向）。
-
  `penetrationDepth`（穿透深度）：角色嵌入地面的距离（标量）。

**计算公式**：

cpp

```cpp
position += hitNormal * penetrationDepth;
```

**例子**：角色从上方掉下，穿透地面 0.3 个单位，法线为 `(0, 1)`（向上），则角色被垂直上推 0.3 个单位，刚好站在地面上。

**缺点**：如果物体堆叠（比如站在移动平台上），直接位移会导致“多米诺骨牌”式的抖动。

---

### 3. 工业级方案：迭代修正（Iterative Correction） \+ 松弛因子（Solver Iterations）

现代物理引擎（Box2D、PhysX）不用“一次性推出去”，而是**分多次、逐步修正**。

**核心算法（顺序脉冲法 Sequential Impulses 的简化版）**：

cpp

```cpp
for (int iter = 0; iter < 5; iter++) { // 通常 5~10 次迭代
    for (每个碰撞对) {
        // 1. 计算当前穿透深度
        float depth = GetCurrentPenetration(bodyA, bodyB);
        if (depth <= 0) continue;

        // 2. 计算修正量（带松弛因子 0.8，防止过冲）
        Vector3 correction = hitNormal * depth * 0.8f;

        // 3. 根据质量分配修正量（重物移动少，轻物移动多）
        float totalMass = bodyA.mass + bodyB.mass;
        bodyA.position += correction * (bodyB.mass / totalMass);
        bodyB.position -= correction * (bodyA.mass / totalMass);
    }
}
```

**为什么需要迭代？**

-
  一次修正一个碰撞对，可能会破坏另一个碰撞对（比如把角色推出地面，但角色撞到了墙壁）。
-
  多次迭代能逐步收敛，达到“所有物体都不重叠”的稳定状态。
-
  **松弛因子（`0.8`）**：防止数值震荡（过冲导致物体来回弹跳）。

---

### 4. 速度修正（防止“粘滞”与“弹射”）

**仅仅修正位置是不够的**。如果不修正速度，角色会“粘”在斜面上（因为速度始终向下，每帧都会再次穿透进去）。

工业级做法：**将速度沿法线方向归零（或反向弹回）**。

cpp

```cpp
// 在位置修正后，立即修正速度
float normalVelocity = Vector3.Dot(velocity, hitNormal);
if (normalVelocity < 0) { // 仅当速度朝向碰撞面时
    // 完全弹性碰撞：速度反转（有反弹）
    velocity -= (1 + restitution) * normalVelocity * hitNormal;

    // 或非弹性碰撞（地面）：将法线方向速度置零
    velocity -= normalVelocity * hitNormal;
}
```

**针对地面**：`restitution = 0`（完全非弹性），`velocity.y` 被清零，角色站在地面上。
**针对墙壁**：`restitution = 0.3`（轻微反弹），角色撞墙会滑下来。

---

### 5. 针对“高速移动”的修正算法（防止穿模）

当子弹或高速角色在一帧内移动距离超过障碍物厚度时，`SweepTest` 可能检测不到碰撞（因为速度太快，完全穿过了薄墙）。

**工业解法：连续碰撞检测（CCD，Continuous Collision Detection）**

-
  **原理**：将 `velocity * dt` 视为一条线段，检测该线段是否与任何几何体相交。
-
  **如果相交**：将角色移动到**刚好碰撞到的位置**（`position += velocity * dt * hitFraction`），然后执行穿透修正。

cpp

```cpp
void MoveWithCCD(Vector3 start, Vector3 velocity, float dt) {
    RaycastHit hit = Physics.Raycast(start, velocity.normalized, velocity.magnitude * dt);
    if (hit.hit) {
        // 1. 移动到碰撞点（不穿透）
        position = start + velocity * dt * hit.fraction;
        // 2. 执行穿透修正（确保不陷进墙面）
        position += hit.normal * 0.01f; // 微小的偏移
        // 3. 速度修正（沿墙面滑动）
        velocity -= Vector3.Dot(velocity, hit.normal) * hit.normal;
    } else {
        position = start + velocity * dt;
    }
}
```

### 6. 针对“移动平台”的特殊修正（你之前问过的）

当角色站在一个正在上升的电梯上时：

-
  **如果不修正**：电梯把角色“抬”起来，但重力每帧把角色“压”下去，角色会在电梯表面上下抖动。
-
  **工业做法**：在穿透修正中，**不仅修正位置，还要将角色的速度继承平台的速度**。

cpp

```cpp
// 在碰撞修正时
if (hit.body.isMovingPlatform) {
    // 将平台的移动速度传递给角色
    velocity.y += hit.body.velocity.y;
}
```

### 7. 在你的 ECS 系统中的实现（时序与组件）

结合我们之前的 ECS 架构，穿透修正应该放在 **`CollisionSystem`** 中，且严格遵循以下时序：

| 执行顺序 | System 名称 | 职责 |
| --- | --- | --- |
| **Step 1** | **GravitySystem** | `velocity.y += GRAVITY * dt` |
| **Step 2** | **VelocitySystem** | 应用输入，计算最终 `velocity` |
| **Step 3** | **CollisionSystem（核心）** | **1. 执行 `SweepTest` 检测碰撞 <br> 2. 计算 `penetrationDepth` 和 `hitNormal` <br> 3. 执行**位置修正**：`position += hitNormal * depth * 0.8` <br> 4. 执行**速度修正\*\*：`velocity -= normalVel * hitNormal` <br> 5. 如果穿透依然存在，再迭代 3~5 次 |
| **Step 4** | **IntegrateSystem** | `position += velocity * dt`（应用最终位移） |

**组件数据**（存储在 `PhysicsComponent` 中）：

cpp

```cpp
struct PhysicsComponent {
    Vector3 velocity;
    float mass;
    float restitution;        // 弹性系数（0 ~ 1）
    bool isKinematic;         // 是否由动画驱动（如平台）
    Vector3 lastFramePosition; // 用于计算速度/避免穿透
};
```

### 8. 常见陷阱与工业级调优

| 陷阱 | 后果 | 工业解法 |
| --- | --- | --- |
| **松弛因子太大（\>1）** | 角色弹飞（过冲） | 固定 `0.8` 或动态调整（如 `0.9` 用于高弹性物体） |
| **迭代次数太少** | 角色依然微穿透（看起来陷地） | 最少 5 次迭代，移动平台场景 10 次 |
| **CCD 检测不到旋转** | 旋转的薄片穿模 | 使用 **凸包分解（Convex Decomposition）** 或 **球体包裹** |
| **质量为零的静态物体** | 除以零导致 NAN（非数字） | 静态物体质量视为 `INF`（无穷大），只移动动态物体 |

---

### 最终总结

**穿透修正的本质，就是“先允许物理错误发生，再用迭代算法把错误纠正到人眼不可见的程度”。**

1.
   **位置修正**：沿法线推出重叠区域（带有松弛因子防止过冲）。
2.
   **速度修正**：消除沿法线方向的相对速度（防止再次穿透）。
3.
   **迭代求解**：用多次迭代处理多物体堆叠（如人站在箱子上，箱子站在地面上）。
4.
   **CCD**：用射线检测防止高速穿模。

在你的 ECS 架构中，将 **`CollisionSystem`** 设计为可迭代的独立 System，每一帧执行 5~10 次内部循环，你就可以拥有媲美《超级马里奥：奥德赛》的物理稳定性。😊
