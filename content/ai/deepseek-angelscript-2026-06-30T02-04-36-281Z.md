## Assistant

引用计数（Reference Counting）是 AngelScript 用来管理脚本对象生命周期的核心机制。它的原理很简单：**每个脚本对象都带着一个计数器，记录有多少个地方正在“使用”它。当这个数字归零时，对象就会被自动销毁。**

这种机制让你在 C\+\+ 端持有脚本对象时，不需要担心它什么时候会被销毁，只要正确地增减计数，AngelScript 会自动在合适的时机清理内存。

### 🔢 工作原理：一个简单的计数过程

我们可以把引用计数的过程想象成一次聚会签到：

1.
**对象创建**：当通过 `factory` 创建一个脚本对象时，它的初始引用计数是 **1**。可以理解为“对象自己拥有自己”。
2.
**增加引用 \(`AddRef`\)**：每当一个新的 C\+\+ 变量、脚本句柄或 `asIScriptContext` 持有了这个对象的指针，就应该调用一次 `AddRef()`，计数加 1。
3.
**减少引用 \(`Release`\)**：每当一个持有者不再需要这个对象时，就应该调用一次 `Release()`，计数减 1。
4.
**自动销毁**：当引用计数通过 `Release()` 归零时，AngelScript 会立即调用对象的析构函数并释放其占用的内存。

### 🧩 谁在操作引用计数？

在 AngelScript 的世界里，主要有三方在操作这个计数器：

-
**AngelScript 引擎本身**：当你在脚本中创建对象、传递句柄或让对象超出作用域时，引擎会自动调用 `AddRef` / `Release`。
-
**脚本代码**：脚本中的句柄（`@`）赋值、函数参数传递等操作，都会由引擎在幕后自动维护计数。
-
**C\+\+ 宿主代码（你）**：这是你需要显式关注的部分。当你通过 `asIScriptObject` 等接口在 C\+\+ 中持久地保存一个对象指针时，**必须手动调用 `AddRef` 和 `Release`**。

### 🔄 典型场景与对比

为了更清晰，我们看两个常见的场景：

| 场景 | 操作 | 说明 |
| --- | --- | --- |
| **临时使用** \(如从Context获取对象\) | **不调用** `AddRef` | 对象由 Context 持有，只要 Context 存在，对象就是安全的。适合短时间、同步的处理。 |
| **长期持有** \(如在C\+\+容器中存储\) | **必须调用** `AddRef` | 对象需要独立于 Context 存活。你在获取指针后必须调用 `AddRef`，声明你的“所有权”。 |

### ⚠️ 避坑指南

引用计数虽然简单，但在 C\+\+ 与脚本混用时，有两个典型陷阱需要特别注意：

1.
**悬空指针（Dangling Pointer）**：你保存了对象指针，但没有调用 `AddRef`。Context 释放后，对象被销毁，你的指针就成了悬空指针，任何访问都会导致程序崩溃。
2.
**内存泄漏（Memory Leak）**：你调用了 `AddRef`，但忘记在适当的时候调用 `Release`。对象因此永远不会被销毁，内存会一直占用，导致泄漏。

### 💎 总结与实践建议

使用引用计数的规则可以总结为一句话：**“谁持久持有，谁负责增加；谁不再需要，谁负责减少。”**

一个安全的通用模式如下：

cpp

```cpp
// 1. 获取对象指针
asIScriptObject* obj = /* 从 Context 等方法获取 */;

// 2. 如果你打算长期持有，立即增加引用
obj->AddRef();

// 3. ... 在系统其他部分使用 obj ...

// 4. 当你不再需要时，务必减少引用
obj->Release();
// 注意：Release 后不要再使用 obj，因为它可能已被销毁
```

理解并严格遵守这个规则，是安全地将 AngelScript 对象集成到 C\+\+ 代码中的基础。如果你打算在 C\+\+ 端设计一个“对象池”或“句柄管理器”，理解引用计数会更关键。需要我继续讲讲如何结合 `weakref` 来解决循环引用的问题吗？
