# LuaJIT vs AngelScript 完整版对比（C++ 自研引擎精准选型）

先给核心结论：

1. **纯脚本密集数值运算**：**LuaJIT JIT 模式更强**，极限性能更接近原生 C++；
2. **高频 C++ ↔ 脚本双向互调（游戏常态）**：**AngelScript 天生占优**，普通绑定场景开销更低、更稳定；
3. **移动端手游、需要线上热更新、跨平台全覆盖**：必选 LuaJIT；
4. **PC / 主机单机、3A、看重强类型工程稳定、本地即时热重载、代码和 C++ 风格统一**：必选 AngelScript。

## 一、底层架构与类型系统（本质差距）

### LuaJIT

- **动态弱类型**，运行时类型推导，变量随时改类型，编译只查语法，**类型错误全部运行时暴露**，大型项目后期隐性 BUG 极多。
- OOP 靠 table + 元表模拟，没有原生类、继承、重载，团队代码规范极易混乱。
- 完整兼容 Lua5.1，附带**FFI 扩展**，可以直接裸调用 C 函数，是它独有的王牌特性。
- VM 体积极小，整体仅**90KB 左右**，内存占用极低。

### AngelScript

- **静态强类型**，变量必须声明类型，编译字节码阶段拦截类型错误，运行时崩溃概率远低于 LuaJIT。
- 语法**几乎复刻 C++**，原生支持类、单继承、接口、函数重载、命名空间，C++ 程序员几乎零学习成本。
- 原生句柄机制对标 C++ 智能指针，跨语言对象生命周期和 C++ 高度对齐。
- 虚拟机体积约**250KB**，内存走势可预测，GC 抖动可控性更好。

## 二、性能详细实测（游戏两大场景）

### 场景 1：纯脚本内部密集计算（循环、数学、向量运算）

1. **PC/Android 开放平台（可开启 JIT）** LuaJIT JIT 编译后性能极强，复杂循环运算**普遍快 AngelScript 1.2~2 倍**，是最快的嵌入式脚本之一，逼近 C++ 性能。
2. **iOS、主机平台（系统禁止动态内存执行，JIT 被锁死）** LuaJIT 只能运行**解释器模式**，性能大幅缩水，此时**AngelScript 字节码执行速度反超 LuaJIT 解释版 1.5~2 倍**。

### 场景 2：游戏最常用：C++ 引擎高频调用脚本 / 脚本频繁调用 C++（帧循环、组件回调）

1. **AngelScript 优势明显** 原生为 C++ 绑定设计，注册类型 / 函数后，直接按照 C++ 调用约定互通，参数编组简单，**没有 Lua 栈操作开销**，每帧几百上千次跨语言调用时，稳定性和耗时完胜原生 Lua 绑定；Urho3D 实测同游戏逻辑，AS 帧率普遍高于 Lua 体系。
2. **LuaJIT 普通绑定（sol2/tolua）短板** 传统 API 必须压栈、弹栈操作参数，频繁互调栈开销很高；**补救方案：FFI**：LuaJIT 独有的 FFI 可以绕过 Lua 栈，直接调用 C 函数，能把交互性能拉高数倍，但需要手动写 C 函数原型，增加开发复杂度，C 反向调用 Lua 依然开销大。

### 补充：执行确定性

AngelScript 字节码执行耗时高度稳定，适合主机硬实时帧率要求；LuaJIT 的 JIT 编译、GC 回收会带来不可预测的性能尖峰。

## 三、C++ 绑定开发难度（自研引擎核心痛点）

### AngelScript

1. **零第三方依赖**，自带完整绑定 API，一行代码即可注册全局函数、C++ 类、成员变量、重载函数、const 引用。
2. 脚本可以**直接继承 C++ 导出的基类**，引擎组件架构完美互通，虚函数、多态无缝衔接，生命周期天然统一，野指针、内存泄露更容易管控。
3. 上手简单，绑定代码和业务逻辑风格统一。

### LuaJIT

1. 原生 C API 繁琐，必须依赖 **sol2、tolua++、xlua** 第三方绑定库才能高效开发。
2. 重载、虚函数、复杂继承封装麻烦，极易出现**栈失衡、引用计数错误**等低级问题。
3. 脚本无法继承 C++ 类，只能封装接口调用；FFI 仅能单向脚本调用 C，C 主动回调的短板无法解决。

> 简单总结：从零手写绑定，AngelScript 效率碾压 LuaJIT；使用成熟 sol2 框架，LuaJIT 绑定够用，但上限不如 AS。

## 四、热重载 / 热更新（手游 vs 单机分水岭）

### LuaJIT（手游热更新行业标杆）

1. **远程线上热更新生态极度成熟**：运行时动态重载脚本文件、替换函数，游戏不重启进程即可下发逻辑补丁，国内手游全部标配 LuaJIT 热更方案（XLua、Tolua），踩坑方案、案例数不胜数。
2. 模块粒度灵活，配合`require`机制可以精准局部热更；缺点是动态替换类、大规模架构重构难度大。
3. 协程是语言原生特性，做技能状态机、异步逻辑极其顺手。

### AngelScript

1. **本地编辑器热重载无敌**：UE AngelScript、《双人成行》生产线，编辑器运行游戏时，保存脚本即可即时刷新逻辑，无需重启进程，开发迭代效率极高。
2. 支持模块动态编译、卸载，适合开发调试；**致命短板：商用移动端远程热更新方案极度稀缺**，社区几乎没有成熟的线上热更框架，几乎不会用于手游线上热补丁。
3. 协程、任务调度内置可用，但语法简洁度弱于 Lua。

## 五、平台兼容性 & 特殊平台限制

### LuaJIT

- 全平台通吃：Windows、Linux、Android、macOS、嵌入式设备全覆盖。
- **硬伤：iOS、PS、Xbox 等封闭主机平台，官方禁止 JIT 动态编译**，JIT 功能直接失效，只能跑解释模式，性能大打折扣。
- Web 平台支持较差，基本不用于 Web 端。

### AngelScript

- **全平台一致性极强**，所有平台均为字节码解释执行，**没有 JIT 平台限制**，iOS、主机、掌机运行性能完全一致，是主机游戏首选脚本。
- 跨平台编译、打包流程简单，字节码跨平台通用。

## 六、生态、人才、沙箱、多线程

### 生态与人手

1. **LuaJIT 生态碾压**：游戏服务器、Cocos、大量网游、工具脚本全覆盖，第三方库（配表、网络、加密、序列化）应有尽有，程序、策划基本都会 Lua，招人成本极低。
2. **AngelScript 垂直小众**，社区聚焦**PC 单机、主机、3A 自研引擎**（Urho3D、EzEngine、Hazelight 工作室），官方文档完善，但全网教程、第三方扩展很少，会 AS 的程序员稀缺。

### 沙箱安全（MOD、防外挂）

1. AngelScript**内置完整沙箱权限机制**，可以精细管控脚本可访问的 C++ 接口、内存、执行时长，做玩家 MOD、第三方脚本防入侵、防外挂天然合适。
2. LuaJIT 沙箱需要完全手动封装实现，隔离成本更高。

### 多线程

1. AngelScript 支持**多虚拟机实例天然多线程运行**，线程安全设计完善。
2. LuaJIT 单个虚拟机非线程安全，多线程必须创建多个独立 VM 隔离，开销更大。

## 七、优缺点汇总

### LuaJIT 优点

1. 体积极小，内存占用低，嵌入式、低端安卓完美适配；
2. JIT 模式纯脚本运算性能顶尖，FFI 高速调用 C；
3. 动态灵活，table 万能容器，配置、数据驱动开发飞快；
4. 手游热更新方案成熟完善，生态庞大，人力成本低。

### LuaJIT 缺点

弱类型导致大型项目后期维护困难；原生 OOP 不规范；封闭平台 JIT 失效；C 反向调用脚本开销偏高。

### AngelScript 优点

1. C++ 同源语法，上手快，后续热点逻辑迁移回 C++ 极其顺滑；
2. 静态类型前置排错，大型长期商业项目稳定性更强；
3. C++ 双向绑定简单高效，跨语言调用稳定，耗时确定性强；
4. 全平台无 JIT 限制，主机平台友好，沙箱、多线程原生完善。

### AngelScript 缺点

生态小众，资料少，人才难找；移动端远程热更新方案匮乏；动态灵活性不足，体积略大。

## 八、最终选型建议

### 选 LuaJIT 的场景

1. **2D/3D 手游、安卓为主，必须线上远程热更新**（国内网游首选）；
2. 需要兼顾客户端 + 游戏服务器共用脚本；
3. 小型团队、快速原型、小游戏、配置与工具脚本；
4. 开发人员熟悉 Lua 生态，追求低成本招人。

### 选 AngelScript 的场景

1. **PC 单机、主机游戏、3A 自研引擎，长期大型商业项目**；
2. 团队主力是 C++ 程序员，想要脚本与底层代码风格统一，长期维护稳定；
3. 核心诉求是编辑器本地即时热重载，不需要手游线上热更；
4. 需要开放玩家 MOD、第三方脚本，对权限沙箱、外挂防护要求高。

### 折中成熟方案（Urho3D 标准架构）

引擎双脚本嵌入：**核心游戏业务、组件逻辑用 AngelScript 保稳定；配置文件、工具脚本、附属逻辑用 LuaJIT 保灵活高效**。
