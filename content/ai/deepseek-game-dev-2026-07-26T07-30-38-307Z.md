### 1. 为什么必须用3D斜坡？（2D投影在这里失效）

在标准横版2D（XY平面）中，斜坡是一个**二维线段**，碰撞检测可以用分离轴定理（SAT）处理。

在2.5D中，斜坡是三维空间中的一个**倾斜平面**（例如：一个从 `(0, 0, 0)` 延伸到 `(1, 1, 1)` 的坡面）。此时：

-
  **角色在XY平面上移动**，但Z轴同时变化（走上坡或下坡）。
-
  **碰撞法线**不再只是2D方向，而是包含Z分量的3D向量。
-
  **如果只用2D多边形处理**：角色在斜坡上会“悬空”或“陷地”，因为2D碰撞无法计算Z轴的高度偏移。

**因此，2.5D斜坡的碰撞检测，必须使用3D碰撞体（如 `btConvexTriangleMesh` 或自定义高度场）。**

---

### 2. 2.5D斜坡与全3D斜坡的本质区别：受限的自由度

虽然用了3D碰撞体，但2.5D游戏的物理**通常不是完整的3D物理**，而是**2.5D物理（或称“受限3D物理”）**。

| 维度 | 全3D游戏（如《塞尔达》） | 2.5D游戏（如《火炬之光》） |
| --- | --- | --- |
| **移动自由度** | 任意方向（X, Y, Z完全自由） | XY平面自由，Z轴受重力/斜坡约束 |
| **碰撞体形状** | 复杂凸包或胶囊体 | 通常用**圆柱体（Cylinder）** 或 **球体（Sphere）**，Z轴方向拉伸 |
| **斜坡响应** | 完整的速度投影 \+ 摩擦力 \+ 弹跳 | 仅将速度投影到斜面切向，Z轴速度受严格限制 |
| **物理引擎** | 全功能物理引擎（PhysX/Bullet） | 轻量级自定义物理，或2D物理引擎 \+ Z轴扩展 |

**核心区别**：在2.5D中，**角色不会因为斜坡而获得Z轴方向的自由飞行能力**。斜坡只是改变角色的高度（Z值），而不会让它像3D游戏那样“飞起来”。

### 3. 2.5D斜坡的碰撞检测算法（工业级方案）

因为2.5D的Z轴运动是受限的，我们可以用**简化的3D碰撞检测**，而不需要引入完整的3D刚体物理。

#### （1）碰撞体表示

-
  **角色**：用**圆柱体（Capsule的Z轴版本）** 或**球体**。
-
  **地形**：用**高度图（Heightmap）** 或 **三角形网格（Triangle Mesh）**。

#### （2）碰撞检测流程（每帧）

cpp

```cpp
void HandleSlopeCollision(Entity& entity) {
    // 1. 获取角色当前位置 (x, y, z)
    Vector3 pos = entity.transform.position;

    // 2. 计算角色脚底的位置（圆柱体底部）
    float footZ = pos.z - entity.collisionHeight / 2;

    // 3. 从脚底位置向下做射线检测（Z轴负方向），获取斜坡高度
    RaycastHit hit = Physics.Raycast(pos.x, pos.y, footZ, Vector3.down, MAX_DISTANCE);

    if (hit.hit) {
        // 4. 计算斜坡在 (x, y) 位置处的高度
        float slopeHeight = hit.point.z;

        // 5. 如果脚底低于斜坡高度，说明角色穿透了斜坡
        if (footZ < slopeHeight) {
            // 6. 位置修正：将角色“抬”到斜坡表面
            entity.transform.position.z = slopeHeight + entity.collisionHeight / 2;

            // 7. 速度修正：将Z轴速度归零（防止再次穿透）
            if (entity.velocity.z < 0) {
                entity.velocity.z = 0;
            }

            // 8. 标记为“接地”
            entity.isGrounded = true;
        }
    }
}
```

**这种“射线检测 \+ 高度修正”的方案**，在2.5D游戏中极为常见，因为它**避免了复杂的3D穿透迭代**，性能开销极小，且足够应对大多数斜坡场景。

### 4. 如果斜坡是“非水平”的（如45度坡道）

对于倾斜方向不规则的斜坡（如Z字形坡道），仅靠垂直射线检测可能不够，因为：

-
  角色可能在斜坡上**水平滑动**，需要沿斜坡切向移动。
-
  需要计算**斜坡法线**，用于修正速度方向。

**工业级解法（位移分离法，我们之前聊过，但扩展到3D）**：

cpp

```cpp
void MoveOnSlope3D(Entity& entity, Vector3 desiredDisplacement) {
    // 1. 检测斜坡法线（通过射线或三角面查询）
    Vector3 slopeNormal = GetSlopeNormal(entity.position.x, entity.position.y);

    // 2. 将期望位移投影到斜坡切平面上
    Vector3 tangent = slopeNormal.GetPerpendicular(); // 注意：在3D中，切平面是一个二维平面
    Vector3 actualDisplacement = desiredDisplacement - dot(desiredDisplacement, slopeNormal) * slopeNormal;

    // 3. 应用修正后的位移（同时更新 X, Y, Z）
    entity.transform.position += actualDisplacement;

    // 4. 速度修正
    entity.velocity -= dot(entity.velocity, slopeNormal) * slopeNormal;
}
```

**注意**：在2.5D中，`desiredDisplacement` 通常包含XY平面的移动和Z轴的重力影响，但**Z轴分量会被斜坡法线重新分配**。

### 5. 在你的ECS中的数据结构与System设计

cpp

```cpp
// 组件定义
struct Transform3D {
    Vector3 position;   // 包含 Z 轴
    Vector3 velocity;
};

struct SlopeCollider {
    float radius;       // XY平面半径
    float height;       // 圆柱体高度
    bool isOnSlope;     // 标记当前是否站在斜坡上
    Vector3 slopeNormal; // 当前斜坡法线（每帧更新）
};

struct SlopeQuery {
    float slopeHeight;  // 斜坡在当前X,Y位置的高度
    Vector3 normal;     // 斜坡法线
    bool hit;
};
```

**System 执行顺序**：

| 执行顺序 | System 名称 | 职责 |
| --- | --- | --- |
| **Step 1** | **GravitySystem** | `velocity.z += GRAVITY * dt` |
| **Step 2** | **HorizontalMoveSystem** | 应用XY平面输入，计算期望位移 |
| **Step 3** | **SlopeDetectionSystem** | 执行**射线检测**，获取当前X,Y位置下的斜坡高度和法线 |
| **Step 4** | **SlopeCorrectionSystem** | **1. 如果 `footZ < slopeHeight`，修正 `position.z` 到斜坡表面 <br> 2. 如果 `isOnSlope`，将速度投影到斜坡切向上 <br> 3. 如果 `velocity.z < 0`，置零** |
| **Step 5** | **CollisionSystem** | 处理水平墙壁碰撞（与标准2D一致） |
| **Step 6** | **ProjectionSystem** | 将3D坐标映射到屏幕坐标 |

### 6. 2.5D斜坡的“视觉陷阱”与工业解法

| 陷阱 | 现象 | 工业解法 |
| --- | --- | --- |
| **斜坡与地面接缝处卡脚** | 角色在斜坡底部或顶部会“粘住”或弹跳 | 在斜坡边缘增加**圆角过渡（Smooth Blending）**，或使用**连续高度场（Continuous Heightfield）** |
| **斜坡上跳跃高度不一致** | 在斜坡上起跳，高度比平地低或高 | 跳跃时**忽略斜坡法线**，强制沿世界Z轴方向起跳（`velocity.z = JUMP_SPEED`） |
| **斜坡上的水平移动速度衰减** | 角色在斜坡上移动变慢（能量损失） | 在速度投影时，**保持切向速度模长不变**（即不损失速度） |
| **多斜坡重叠导致穿透** | 角色站在两个斜坡的交界处，脚底陷入地面 | 使用**分层碰撞掩码**，或对多个射线结果取**最高点** |
