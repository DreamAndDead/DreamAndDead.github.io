### 1. 为什么会损失移动距离？（数学解析）

假设角色在斜面上水平移动，这是一个典型的2D平台跳跃场景：

-
  **本帧期望位移**：角色想要沿水平方向（X轴）移动 **1.0 米**。
-
  **实际执行过程**：
  1.
     **施加重力**：`velocity.y += GRAVITY * dt`（假设此时重力让角色向下移动了 0.1 米）。
  2.
     **应用位移**：`position += velocity * dt`，此时角色既向右（1.0米）又向下（0.1米）移动，形成了一个斜向位移。
  3.
     **碰撞检测**：发现角色穿透了斜面。
  4.
     **穿透修正**：沿斜面法线方向将角色“推”出来，直到刚好不重叠。

**关键问题来了**：法线方向是垂直于斜面的（比如斜向左上方）。当你沿这个方向推角色时，不仅把角色从地里“拔”出来了，**还把角色向右的水平位移也“推”回去了一部分**。最终，角色的水平移动距离可能只有 **0.92 米**，而不是预期的 1.0 米。

**这就是“距离损失”的数学根源。**

### 2. 这种损失会带来什么视觉和手感问题？

-
  **“粘脚”效应**：当玩家沿着斜坡向右上移动时，角色会感觉像踩在“泥潭”里，移动速度比预期要慢。这在竞速游戏或精确平台跳跃中是致命的。
-
  **非对称手感**：在左右对称的斜坡上，角色向右走和向左走的“滑度”可能不一样（取决于法线方向和位移方向的夹角）。
-
  **跳跃轨迹偏移**：如果角色在起跳瞬间发生了穿透修正，跳跃的初始轨迹会被“掰弯”，导致玩家感觉操作不跟手。

---

### 3. 工业界的完美解法：在“投影前”就分离位移

为了彻底消除距离损失，物理引擎不采用“先移动、再修正”的策略，而是采用 **“先检测、再移动（Cast then Move）”** 或 **“位移分离（Displacement Separation）”** 算法。

**核心思想**：**将本帧的期望位移分解为“沿斜面方向”和“垂直斜面方向”两个分量，然后只保留沿斜面方向的分量来移动角色。**

cpp

```cpp
// 工业级做法（解决距离损失的黄金标准）
void MoveWithoutSlip(Vector3 startPos, Vector3 desiredDisplacement, float dt) {
    // 1. 执行 SweepTest，检测如果按期望位移移动，会撞到哪个斜面
    RaycastHit hit = Physics.SweepTest(startPos, desiredDisplacement, desiredDisplacement.magnitude);

    if (hit.hit) {
        // 2. 关键步骤：将位移向量分解为“沿斜面切向”和“沿斜面法向”
        Vector3 hitNormal = hit.normal;
        Vector3 tangent = hitNormal.GetPerpendicular(); // 切向（即斜面方向）

        // 3. 计算期望位移在切向上的分量（这是“有效移动距离”）
        float tangentComponent = Vector3.Dot(desiredDisplacement, tangent);

        // 4. 仅保留切向分量作为最终位移（彻底丢弃法向分量）
        Vector3 actualDisplacement = tangent * tangentComponent;

        // 5. 应用最终位移（不会产生任何穿透，因为位移完全沿斜面方向）
        position = startPos + actualDisplacement;

        // 6. 速度修正：将速度也投影到切向上（保持与位移一致）
        velocity = tangent * Vector3.Dot(velocity, tangent);
        if (hitNormal.y > 0.5f) velocity.y = 0; // 如果是地面，将垂直速度清零
    } else {
        // 没有碰撞，正常移动
        position = startPos + desiredDisplacement;
    }
}
```

**这个算法的绝妙之处在于**：

-
  **它不是在“碰撞后”修正，而是在“移动前”就决定了要往哪走**。
-
  **期望位移中的“法线分量”被完全丢弃了**，所以角色永远不会尝试走进斜面内部，也就永远不会触发穿透修正。
-
  **水平移动距离完全保留**（`desiredDisplacement.x` 在切线上的投影接近于 1.0），不会有任何“吃距离”的感觉。

### 4. 如果必须保留“法线方向”的移动怎么办？（比如跳跃）

上面的算法在“水平移动”时非常好用，但如果角色正在跳跃（`velocity.y > 0`），我们不能把法线分量完全丢弃，否则角色会无法跳离地面。

**工业级混合做法**：

cpp

```cpp
void MoveWithSlipAndJump(Vector3 startPos, Vector3 velocity, float dt) {
    Vector3 desiredDisplacement = velocity * dt;

    // 1. 先检测碰撞
    RaycastHit hit = Physics.SweepTest(startPos, desiredDisplacement, desiredDisplacement.magnitude);

    if (hit.hit) {
        // 2. 分离法线分量和切向分量
        Vector3 normal = hit.normal;
        Vector3 tangent = normal.GetPerpendicular();

        float normalComponent = Vector3.Dot(desiredDisplacement, normal);
        float tangentComponent = Vector3.Dot(desiredDisplacement, tangent);

        // 3. 关键判断：如果法线分量指向“脱离地面”（即向上移动）
        if (normalComponent > 0) {
            // 保留法线分量（让角色能跳起来）
            position = startPos + tangent * tangentComponent + normal * normalComponent;
            // 速度保持不变（保留向上的速度）
        } else {
            // 法线分量指向“压入地面”（即向下移动），则丢弃
            position = startPos + tangent * tangentComponent;
            // 将垂直速度清零
            velocity.y = 0;
        }
    } else {
        position = startPos + desiredDisplacement;
    }
}
```

### 5. 在你的 ECS 架构中的实现（System 拆分）

结合我们之前聊的物理更新顺序，你应该将“位移分离”逻辑放在 **`CollisionSystem`** 中，替代简单的“位置修正”：

| 执行顺序 | System 名称 | 核心职责 |
| --- | --- | --- |
| **Step 1** | **GravitySystem** | `velocity.y += GRAVITY * dt` |
| **Step 2** | **VelocitySystem** | 应用输入，计算最终 `velocity` |
| **Step 3** | **CollisionSystem（重构版）** | **1. 执行 `SweepTest` <br> 2. 计算法线和切向 <br> 3. 将位移投影到切向上（丢弃法向分量） <br> 4. 应用修正后的位移 <br> 5. 修正速度（将其投影到切向）** |
| **Step 4** | **IntegrateSystem** | `position += velocity * dt`（应用最终位移） |

**注意**：这个方案中，**`IntegrateSystem` 不再承担实际的位移计算**，它只负责更新位置。真正的移动逻辑已经完全移到了 `CollisionSystem` 中。

### 最终总结

你敏锐地察觉到了“沿法线弹出”会导致水平距离损失，这个问题在物理引擎中被称为 **“投影误差”**。

**工业界的标准解法是：在移动前就进行位移投影（Displacement Projection），而不是在移动后再进行位置修正。**

-
  **错误的做法**：先移动 → 穿透 → 沿法线修正位置（会损失距离）。
-
  **正确的做法**：先计算期望位移 → 分解为法线和切向 → 丢弃法向分量 → 仅沿切向移动（零距离损失）。

这种“投影前分离”的策略，是《蔚蓝》、《超级马里奥》等顶级平台跳跃游戏能够拥有“像素级精确手感”的底层秘密。😊
