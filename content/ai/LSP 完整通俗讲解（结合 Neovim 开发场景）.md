# LSP 完整通俗讲解（结合 Neovim 开发场景）

LSP 全称 **Language Server Protocol（语言服务器协议）**，由微软为 VSCode 制定的**标准 JSON 通信协议**，目的：**把「代码分析、补全、跳转、报错、重构」等语言逻辑，统一放到独立的后台程序（语言服务器），编辑器只做前端界面**。

## 一、核心架构（三层）

1. **客户端（Client）**
   Neovim / VSCode 就是客户端，你在编辑器打字、查定义、重命名，把请求按照 LSP 协议打包发出去。
   Neovim 客户端库：`neovim/nvim-lspconfig`。
2. **通信层**
   底层 STDIO/TCP，上层固定 LSP JSON 协议，**所有语言遵循同一套消息格式**。
3. **语言服务器（Language Server）**
   独立后台程序，专门解析对应编程语言的源码、语法树、类型系统。
   比如：

- Lua：`lua-language-server`
- C/C++：`clangd`
- Angelscript：`angel-lsp`
- Python：`pyright`

## 二、LSP 解决了什么痛点？

### 老式方案（没有 LSP）

编辑器要为每一门语言单独写一套补全、语法分析插件。
 写一套 C++ 插件、一套 Lua 插件、一套 AS 插件，**重复造轮子，开发成本极高，功能参差不齐**。

### LSP 标准化方案

1. 每门语言只需要**开发一个语言服务器**（全世界通用，VSCode、Neovim、Sublime 全都能用）；
2. Neovim 的 LSP 客户端统一对接所有服务，**一套客户端，通吃所有编程语言**。

## 三、LSP 能提供的完整能力（日常开发功能）

1. **代码补全**：变量、函数、类、参数提示
2. **诊断报错**：实时语法错误、类型警告、未定义变量行内标红
3. **跳转**：`gd` 跳定义、`gD` 跳声明、`gr` 查看所有引用
4. **悬浮文档**：光标`K`查看函数注释、参数说明
5. **代码重构**：批量重命名变量 `rn`、自动导入、代码操作 `ca`
6. **格式化**：自动缩进、排版代码
7. **代码大纲、类型层级、接口实现查找**

## 四、LSP 和 DAP 的区别（极易搞混）

很多人分不清 LSP 和 DAP，一张表讲清本质：

| 协⁠议 | 全⁠称 | 用⁠途 | 工⁠作⁠阶⁠段 |
| --- | --- | --- | --- |
| LSP | 语⁠言⁠服⁠务⁠器⁠协⁠议 | **静⁠态⁠代⁠码⁠分⁠析**：编⁠码⁠时⁠补⁠全、报⁠错、跳⁠转、重⁠构 | 写⁠代⁠码⁠阶⁠段 |
| DAP | 调⁠试⁠适⁠配⁠器⁠协⁠议 | **运⁠行⁠时⁠调⁠试**：程⁠序⁠运⁠行⁠时⁠断⁠点、单⁠步、看⁠运⁠行⁠时⁠变⁠量、堆⁠栈 | 程⁠序⁠运⁠行⁠阶⁠段 |

简单记：
**写代码用 LSP，跑程序调试用 DAP**。
 你写 Angelscript/C++：编码靠 LSP，运行断点调试靠 DAP。

## 五、Neovim 里 LSP 的工作流程

1. 安装对应语言的 **language server 服务端程序**（Mason 一键下载）；
2. `nvim-lspconfig` 启动服务进程，建立 Neovim 与服务端的通信；
3. 打开对应后缀文件，自动发送文件内容给服务端；
4. 服务端解析代码，返回补全、报错、跳转位置；
5. 客户端接收结果，在 Neovim 界面展示。

## 六、核心配套插件（Lazy 标配）

1. `neovim/nvim-lspconfig`：官方 LSP 客户端，一键启动各类语言服务；
2. `williamboman/mason.nvim`：图形化一键安装各类 LSP Server、DAP 适配器、格式化工具；
3. `hrsh7th/nvim-cmp`：把 LSP 的补全结果做成可视化自动补全弹窗；
4. `nvim-treesitter`：语法高亮（语法解析，和 LSP 互补，不属于 LSP）。

## 七、极简示例：Lua LSP 流程

1. Mason 安装 `lua-language-server`；
2. lspconfig 配置自动启动该服务；
3. 打开 `.lua` 文件，LSP 自动生效；
4. 输入 `require(` 自动补全模块，`gd` 跳转函数定义，写错变量实时报错。

## 八、针对你的 Angelscript

1. Angelscript LSP：`angel-lsp`，负责 `.as` 文件编码时的语法提示、API 补全、语法检查；
2. Angelscript DAP：引擎内嵌 cppdap 实现 DAP 协议，负责脚本运行时断点调试； 二者搭配，完成完整的开发 + 调试闭环。

## 总结

1. LSP 是**静态编码的标准化通信协议**，分离编辑器与语言解析逻辑；
2. 语言服务端是语言核心，Neovim 只是客户端；
3. LSP 管「写代码」，DAP 管「调运行程序」，两套协议各司其职。
