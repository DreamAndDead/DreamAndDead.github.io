# SDL2 Audio 原生**没有原生 24bit 整型格式**完整说明 + 全套解决方案

## 一、核心结论

1. **SDL2 底层枚举没有 `AUDIO_S24` 24 位整型格式**，`SDL_AudioFormat` 原生只支持：`U8/S8、S16、S32整型、F32浮点`，**不支持原生 24bit 整数输出硬件**。
2. `SDL_LoadWAV` 原生无法直接解析 24bit WAV，加载会报错；SDL_mixer 底层强制以 16bit 混音输出，同样不原生接纳 24bit。
3. 但**可以曲线兼容 24bit 素材**，两种正规方案：
   - 方案 A：把 24bit 样本封装进**32 位整型 (S32)** 或者 **32 位浮点 (F32)** 载入 SDL，内部浮点混音，最后下发硬件转为 16bit（专业游戏音频首选）。
   - 方案 B：前期在 Reaper 批量把**24bit 母版提前导出为 16bit WAV**，彻底绕开问题，适配 SDL 生态。
4. SDL3 新增了 24bit 格式支持，但目前工程主流还是 SDL2。

## 二、为什么我们 Reaper 要用 24bit？和 SDL 运行时不冲突

24bit 只是**制作母版格式**，用来混音、EQ、压缩时保留动态余量，防止处理过程产生量化噪声；
**游戏最终硬件声卡硬件输出，本来就都是 16bit**。
 SDL 只负责运行时播放，不需要硬件输出 24bit，24bit 只存在于素材处理阶段。

## 三、方案 1：代码读取 24bit WAV，转 S32/F32 送入 SDL（代码方案，不修改素材）

### 1. 问题根源

SDL 自带`SDL_LoadWAV`不识别 24bit PCM，需要用轻量单头头文件库 **dr_wav** 手动解析 24bit WAV，读取原始 24bit 样本。

- dr_wav 完美读取 8/16/24/32bit WAV，zlib 协议完全开源商用，完美搭配 SDL。

### 2. 数据映射规则（24bit → 32bit）

24bit 样本是**3 字节对齐存放**，把 24bit 有符号样本左移 8 位，放进 32 位 int 高位，低位补 0，即可完整无损存入`AUDIO_S32`格式：

```plaintext
24bit有效数据： bits 23~0
左移8位 → 存入S32的 bits 31~8，低位空余8bit
后续转16bit时，右移8位即可还原，无精度丢失。
```

### 3. SDL 音频设备打开（使用 S32/F32 内部混音）

```cpp
// 打开设备使用32位整型 或 32位浮点（推荐浮点混音，动态余量最大）
SDL_AudioSpec spec;
spec.freq = 48000;
spec.format = AUDIO_S32SYS;  // 或 AUDIO_F32SYS
spec.channels = 1; // 3D音效单声道
spec.samples = 1024;
spec.callback = AudioCallback;
```

回调函数内部用 32bit 浮点做音量混合、分层轨道叠加，**最后在回调末尾，把混合结果高精度转为 16bit 下发硬件**。

### 4. 24bit 转 16bit 的专业做法（必加抖动 Dither）

禁止简单粗暴 `>>8` 截断，低音量会有明显底噪。

1. 简易版：32bit 数据右移 8 位，简单缩放；
2. 游戏专业版：加入**三角抖动噪声 (TPDF Dither)**，把 24→16bit 的量化噪声打散，人耳完全不可闻，混音质量和商业引擎持平。

## 四、方案 2：Reaper 前期批量转 16bit，最简零代码适配 SDL（最推荐你的自研项目）

你的工作流：Reaper 制作 24bit 分层母版 → 导出成品 16bit WAV 给 SDL 使用。

1. Reaper 批量渲染设置 格式：WAV PCM **48000Hz / 16bit Signed**，勾选**抖动 Dither**（Reaper 导出设置自带）。
2. 优势
   - 导出后的文件可以直接用`SDL_LoadWAV`、`SDL_mixer`正常加载，零额外解析代码；
   - 短音效 WAV、长音频转 OGG，完全符合游戏标准格式，完美适配 SDL 生态；
   - 24bit 母版永久存档，后续更换 FMOD/SoLoud 随时可以拿源文件重做。
3. 适用场景：绝大多数 2D 自研游戏、独立项目，音质肉眼不可区分，工作量最低。

## 五、方案 3：升级 SDL3（长期备选）

SDL3 正式加入原生`AUDIO_S24`格式定义，原生支持 24bit 设备读写，但目前生态、兼容性不如 SDL2 成熟，除非新项目从头搭建，否则没必要升级。

## 六、SDL_mixer 额外说明

SDL_mixer 上层混音器**固定内部 16bit 混音总线**，就算载入 32bit 数据，内部依然会转 16bit 混合。
 如果要用 SDL_mixer：

- 最优做法：素材提前转 16bit；
- 高级用法：底层 SDL Audio 用 F32 浮点自定义混音器，不用 mixer 自带混音，自己做多轨分层音效（对标 FMOD 分层逻辑）。

## 七、配套你整套音频管线的最优组合

### 组合 A（简易快速开发）

Reaper (24bit 制作) → 批量导出 **48k 16bit WAV/OGG** → SDL2 + SDL_mixer 直接加载播放。

### 组合 B（进阶自研多轨分层音频，对标 FMOD 简易版）

Reaper 保留 24bit 分轨 WAV 母版 → dr_wav 解析 24bit 为 S32/F32 → SDL 底层 F32 浮点回调做多轨动态分层混音、音量 RTPC 控制、3D 定位 → 回调末尾高精度转 16bit 输出声卡。

## 八、常见误区

1. 误区：必须硬件输出 24bit 音质才好 PC / 游戏声卡绝大多数日常播放都是 16bit 输出，24bit 仅专业录音用，游戏运行时完全没必要硬件输出 24bit。
2. 误区：SDL 不能读 24bit = 不能用 24bit 制作 二者完全无关，制作阶段 24bit 保证混音质量，运行时转为 16bit 是行业标准流程，FMOD/Wwise 最终下发硬件同样会转为 16bit。
3. 不要强行自己硬解析原始 24bit 字节流，优先用 dr_wav 成熟库，避免大小端、对齐、声道解析 bug。
