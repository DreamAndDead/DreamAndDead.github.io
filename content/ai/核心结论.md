# 核心结论

**显示器开启 FreeSync（VRR 自适应同步）后，程序代码必须关闭 VSync（`glfwSwapInterval(0)`），完全不需要开启垂直同步**；同时**严禁 VSync 与 FreeSync 同时打开**，二者原理互斥，同开会叠加延迟、卡顿、锁帧率，直接废掉 FreeSync 低延迟的优势。

## 一、底层原理完全相反，看懂为什么不能一起开

1. **传统 VSync（SwapInterval=1）** 显卡必须**被动等待显示器固定刷新周期**，没到垂直消隐期绝不交换缓冲区，GPU 等屏幕，人为强制对齐固定刷新率，自带等待延迟。
2. **FreeSync（Adaptive-Sync）** 逻辑反过来：**显示器主动迁就显卡**。GPU 渲染完成一帧，立刻发送信号，显示器动态调整当下刷新率，马上刷新画面。刷新率跟着帧率动态浮动，在面板 VRR 区间内直接消除撕裂，全程**没有强制等待**，保留最低输入延迟。

一旦程序强行开启 VSync，等于强制显卡继续等待固定刷新，FreeSync 的动态自适应机制会被锁死，变回普通垂直同步，白花钱买自适应显示器。

## 二、C++ 开发标准代码写法（GLFW/SFML/Raylib）

### 1. GLFW（OpenGL 原生，最常用）

```cpp
// 必须关闭VSync，interval=0
glfwSwapInterval(0);
```

- `0` = 关闭垂直同步，FreeSync 正常生效
- `1` = 开启 VSync，FreeSync 失效

### 2. SFML

```cpp
sf::RenderWindow window;
window.setVerticalSyncEnabled(false); // VSync关闭
```

### 3. Raylib

```cpp
SetWindowState(FLAG_VSYNC_HINT); // 删掉这行，不要开启VSync
```

## 三、必须配套的完整前置条件（缺一不可）

只关代码 VSync 还不够，FreeSync 才能正常工作：

1. **线材与接口**：优先 DP 1.2a 及以上直连线；HDMI 仅 HDMI2.1 高端显示器完整支持，普通 HDMI 基本跑不满 FreeSync。
2. **显示器端开启**：按显示器实体按键进入 OSD 菜单，手动打开 `FreeSync / Adaptive Sync / VRR`。
3. **显卡驱动开启**
   - AMD 显卡：肾上腺素软件内打开 AMD FreeSync；
   - N 卡用 FreeSync 兼容模式：英伟达控制面板开启「G-SYNC 兼容」。
4. 运行模式：全屏 / 无边框窗口模式效果最佳，普通窗口模式部分机型会限制 VRR。

## 四、配套帧率上限怎么设置（最佳搭配方案）

FreeSync 有固定刷新率区间（例如 48Hz ~ 144Hz），帧率超过面板最大刷新率，自适应同步失效，依旧会出现撕裂。
 正确做法：**代码手动设置渲染帧率上限，略低于显示器最高刷新率**，不要开 VSync。
 举例 144Hz 显示器：

- 渲染上限锁 **140FPS**
- 帧率全程落在 48~144Hz 区间内，FreeSync 全程生效，无撕裂、低延迟。

```cpp
// Raylib 示例，设置帧率上限，而非VSync
SetTargetFPS(140);
```

这套组合：**关闭 VSync + FreeSync 开启 + 帧率上限略低于屏幕最大 Hz**，是竞技游戏的最优解。

## 五、特殊的小众例外情况

1. **帧率长期低于 FreeSync 最低下限（比如低于 48FPS）** 画面会卡顿闪烁，此时可以在驱动开启**LFC 低帧率补偿**，显示器自动倍频刷新，不需要开启程序 VSync。
2. **老旧 Linux OpenGL 环境特例** 极少数旧 AMD 驱动要求 OpenGL 上下文开启 VSync 才能激活 FreeSync，属于系统驱动兼容问题，Windows 平台完全不存在这个情况，日常 Windows 游戏开发不用考虑。

## 六、常见误区澄清

1. **误区：不开 VSync 一定会撕裂，FreeSync 没用** FreeSync 的本职就是**不靠 VSync 解决撕裂**，它依靠硬件层面动态刷新率实现，和软件的垂直同步是两套独立方案。
2. **误区：代码不关 VSync，只在显卡驱动关闭就行** 程序内的`SwapInterval`优先级很高，代码强制开启 VSync 时，驱动设置无法覆盖，依旧会触发固定刷新等待。
3. **和你之前的双时钟架构兼容吗？** 完全兼容。渲染可变帧率上限、逻辑 Fixed 固定步、alpha 画面插值，整套架构不受影响，FreeSync 只负责缓冲区交换的硬件时序，不干涉游戏逻辑时间计算。

## 精简总结

1. FreeSync 的核心优势就是**关闭 VSync 实现无撕裂 + 低延迟**，程序必须关闭垂直同步；
2. 代码`SwapInterval(0)` + 显示器 / 驱动开启 FreeSync + 帧率上限略低于屏幕最大刷新率，是标准配置；
3. VSync 和 FreeSync 不要同时启用，会退回传统同步模式，白白增加操作延迟。
