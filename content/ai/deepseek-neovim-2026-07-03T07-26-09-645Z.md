## Assistant

`HeaderFilterRegex` 是 `clang-tidy` 中一个非常关键但容易被忽略的选项。它的作用是**控制 `clang-tidy` 的检查范围**，特别是决定是否检查头文件中的诊断信息。

### 🎯 它解决的问题

默认情况下，`clang-tidy` 会检查分析到的所有头文件，包括你项目引入的第三方库。这会导致：

-
**大量干扰信息**：第三方库的代码风格可能不符合你的规范，产生大量无用的警告。
-
**性能问题**：检查大量库文件会拖慢 LSP 的响应速度。
-
**阅读困难**：在项目文件中很难快速找到真正需要关注的问题。

通过 `HeaderFilterRegex`，你可以将检查范围限定在**你自己项目的头文件**中。

### ⚙️ 配置方法

在 `.clang-tidy` 文件中，通过 `HeaderFilterRegex` 选项来指定一个正则表达式，只有路径匹配该表达式的头文件才会被检查。

yaml

```yaml
# .clang-tidy
Checks: cppcoreguidelines-*,readability-*

# 只检查项目目录下的头文件
HeaderFilterRegex: "^(src/|include/).*\\.(h|hpp)$"
```

**关键点：**

-
`clang-tidy` 会根据编译数据库中记录的**文件路径**来匹配这个正则表达式。
-
如果正则表达式为空或未设置，所有头文件都会被检查，这通常是用户不希望的。
-
如果设置为 `".*"`，则所有头文件都会被检查（包括系统头文件）。

### 🧩 与 `SystemHeaders` 选项配合

除了 `HeaderFilterRegex`，还有一个相关选项 `SystemHeaders`，用于控制是否检查系统头文件（如 `/usr/include/` 下的文件）。

yaml

```yaml
CheckOptions:
- key:   readability-identifier-naming.SystemHeaders
value: false  # 不检查系统头文件
```

**建议组合使用：**

-
`HeaderFilterRegex`：只检查你项目代码所在的目录。
-
`SystemHeaders = false`：忽略系统头文件的检查。

### 📝 实战示例

**项目结构：**

text

```text
my_project/
├── src/
│   ├── main.cpp
│   └── utils.cpp
├── include/
│   └── mylib/
│       └── utils.hpp
├── third_party/   # 第三方库
│   └── json.hpp
└── .clang-tidy
```

**.clang-tidy 配置：**

yaml

```yaml
HeaderFilterRegex: "^(src/|include/mylib/).*\\.(h|hpp|cpp)$"
SystemHeaders: false
```

**效果：**

-
`src/main.cpp` → 会被检查 ✅
-
`include/mylib/utils.hpp` → 会被检查 ✅
-
`third_party/json.hpp` → **不会被检查** ❌
-
系统头文件（如 `iostream`）→ **不会被检查** ❌

### 🛠️ 在 Neovim 中验证

配置完成后，你可以这样验证：

1.
在 `src/` 目录下的代码中故意制造一个命名规范问题，观察 LSP 是否提示。
2.

3.
查看 `clangd` 日志（`:LspLog`），确认 `clang-tidy` 跳过了第三方库文件。

### 💡 常见正则表达式写法

| 场景 | 正则表达式 |
| --- | --- |
| 只检查 `src/` 和 `include/` 目录 | `"^(src/\|include/).*"` |
| 只检查当前目录及子目录 | `"^.*"` |
| 只检查特定项目目录 | `"^/home/user/project/.*"` |
| 不检查任何头文件 | `""`（留空） |

正确配置 `HeaderFilterRegex` 能显著提升 `clangd` \+ `clang-tidy` 组合的使用体验，让你专注于项目代码本身的代码质量问题。
