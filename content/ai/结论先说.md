# 结论先说

分两种情况：**手动写死文件路径** / **GLOB 动态搜集文件**，要不要 `--fresh(重新configure)` 完全不一样，**绝大多数新增 exe，只需要重新 configure，建议用 fresh，不需要手动删文件夹**。

## 1、手动写死 `add_executable`（现代标准写法，推荐）

### 场景：

一开始 CMakeLists 没有这个目标，**新增一行 add_executable (MyTest main.cpp ...)**
 或是给已有的 exe **新增 / 删减源码文件（target_sources）**。

✅ **必须重新 configure（建议带 --fresh）**

```cmake
# 新增目标
add_executable(MyTest test/main.cpp)
# 或者给现有exe加文件
target_sources(App PRIVATE src/new.cpp)
```

原因：
 CMake 初次 configure 才会解析目标列表、文件列表，旧缓存不会自动发现新增的 Target，直接 build 会提示目标不存在。

执行命令：

```bash
cmake --preset 你的预设 --fresh
# 之后才能构建新程序
cmake --build --preset build预设 -t MyTest
```

## 2、只是往已存在的 exe 里加源码，文件已经写在 target_sources 内

只是修改源码内容，**CMake 脚本一行没动**
 👉 **完全不需要 refresh /configure，直接 build 即可**，Ninja 增量编译自动识别文件改动。

## 3、危险写法：file (GLOB) 自动搜集文件（坑点）

```cmake
file(GLOB SRC_LIST src/*.cpp)
add_executable(App ${SRC_LIST})
```

此时**新建 cpp 文件，CMake 不会自动扫描**，哪怕文件存在，也不会加入编译列表。
 哪怕你只是新增文件、不改 CMake 文本，**依旧必须重新 configure（fresh）**，CMake 才会重新执行 GLOB 扫描。

> 现代 CMake 规范：禁止用 GLOB 搜集源码，就是为了规避这种必须反复刷新的问题。

## 4、什么情况不用 fresh，只普通 configure 就行？

```bash
cmake --preset xxx
```

不加 `--fresh` 也能刷新新增的 exe 目标。
 区别：

1. `cmake --preset xxx`：增量读取缓存，只更新改动部分，速度快，适合只增目标、不改工具链 / 全局变量；
2. `cmake --preset xxx --fresh`：清空全部缓存，完全重建，**切换工具链、改 toolchain、改预设、报错异常时必用**。

日常单纯新增 executable：普通 configure 够用；
 如果你刚切换过编译器（MSVC ↔ Clang）、改过 toolchain，直接 `--fresh` 更稳妥，避免缓存残留。

## 5、精简日常操作口诀

1. **新加 exe 目标 / CMakeLists 改动**`cmake --preset xxx`（常规刷新），异常就上 `--fresh`
2. **只改 cpp 代码，CMake 不动** 直接 build，啥刷新都不用
3. **GLOB 模式新增源码文件** 必须重新 configure
4. **切换工具链、改 Preset 参数** 强制 `--fresh`

## 补充：和 compile_commands.json 的关系

新增 exe / 源码后，只有重新 configure，才会更新 `compile_commands.json`，clangd 才能识别新文件，所以配合 LSP 开发，改完 CMake 务必刷新一次配置。
