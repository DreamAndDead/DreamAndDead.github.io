## User

2D横版游戏是如何处理重力的？当角色站在平台上时也会有重力吗？还是说只是在空中才施加重力？

## Assistant

这个问题问得非常细致，直接触及了2D横版游戏物理（Platformer Physics）的核心设计差异。

直接给你一个工业级的结论：**在绝大多数2D横版游戏（尤其是动作/平台跳跃类）中，重力是始终存在的（Always On），但角色的“运动状态”决定了重力最终是被“应用”还是被“抵消/限制”。**

下面是具体的实现原理和底层逻辑：

---

### 1. 重力处理的三种主流模式

#### （1）始终施加，但靠碰撞系统抵消（最正宗，推荐）

角色每帧都受到向下的加速度（如 `velocity.y -= gravity * dt`）。
当角色站在地面（Platform）上时，碰撞系统检测到角色与地面重叠，会**强行将角色“弹”出地面（位置修正）**，并将 `velocity.y` 设为 `0`。

-
  **状态**：重力一直在作用，只不过每帧都被碰撞响应给“按住了”。
-
  **优点**：物理最真实，从“站立”到“跳跃”的过渡极其平滑（没有状态切换的毛刺）。
-
  **缺点**：如果碰撞响应做得不好，角色会“陷地”或“抖动”。

#### （2）分状态切换（简易模式）

物理更新时判断角色状态：

-
  **在空中**：施加重力。
-
  **在地面**：将重力设为 `0` 或完全不调用重力计算。
-
  **优点**：代码极简，易于理解。
-
  **致命缺点（工业界几乎不用）**：当你站在平台边缘走出去时，如果重力从 `0` 瞬间变为 `-9.8`，角色会感觉“粘”在地面上，起跳响应有延迟，手感会变得非常“肉”。

#### （3）混合模式（针对“平台边缘”的顶级优化）

很多3A级平台跳跃游戏（如《蔚蓝》、《雷曼》）采用这种逻辑：
重力始终存在，但在地面时，重力值不是 `-9.8`，而是一个**极小的“粘滞力（Stick Force）”**（如 `-0.5`），用来将角色“吸”在地面上，防止角色因为浮点数误差而飘起来。一旦检测到脚下悬空，瞬间切换回标准重力。

---

### 2. 站在平台上时，重力的底层表现（物理帧的细节）

假设你站在一个匀速移动的平台上。如果只是把 `velocity.y` 设为 `0`，角色会**被平台甩下去**（因为平台移动了，角色在原地）。

因此，工业级处理要分两步走：

1.
   **重力应用**：每帧先加上重力（`velY += gravity * dt`）。
2.
   **平台速度传递（Velocity Inheritance）**：当碰撞系统检测到站在平台上时，**强制将角色的水平速度（`velX`）和垂直速度（`velY`）赋值为平台当前帧的运动速度**，然后再将 `velY` 归零（或设一个小负数）。

cpp

```cpp
// 伪代码（每帧更新）
void UpdatePlayer(float dt) {
    // 1. 默认施加重力（不管在不在空中）
    velocity.y += GRAVITY * dt;

    // 2. 水平输入处理
    velocity.x = inputAxis * MOVE_SPEED;

    // 3. 碰撞检测与响应（核心）
    CollisionResult result = Physics.CheckCollision(position, velocity, dt);
    if (result.hitGround) {
        // 如果撞到了地面，强制修正垂直速度为0（抵消重力）
        velocity.y = 0;
        // 关键：继承平台速度（如果平台在动）
        velocity.x += result.platformVelocity.x;
        isGrounded = true;
    } else {
        isGrounded = false;
    }

    // 4. 更新位置
    position += velocity * dt;
}
```

---

### 3. “只有空中才加重力”为什么手感会变差？

如果你的代码写成这样：

cpp

```cpp
if (!isGrounded) velocity.y += GRAVITY * dt;
```

当角色在空中时，重力将速度累加到很大。当角色落地时，重力突然消失，且速度被清空。
这会导致**角色像是“黏”在了地面上**。因为当角色想要起跳时，跳跃系统需要：

1.
   检测到“地面”状态。
2.
   施加向上的初始速度（`velocity.y = JUMP_SPEED`）。
3.
   因为重力在“地面”状态被禁用了，角色起跳的第一帧没有重力下压，起跳高度会突然变得极高（跳跃力度感失控）。

**正确做法**：永远不判断 `if (isGrounded)` 来决定是否加重力，而是用**碰撞响应**来决定速度是否被重置。

---

### 4. 浮点数精度与“下平台（One-Way Platform）”

在2D横版游戏中，很多平台允许**从下往上穿**（One-Way Platform）。
这种平台的重力处理极其考验代码功底：

-
  **逻辑**：重力依然每帧应用。碰撞检测时，如果角色当前的 `velocity.y >= 0`（正在下落或静止），则判定平台是实心的，角色站在上面，**强制 `velY = 0`**。
-
  **如果 `velocity.y < 0`（正在上升）**：碰撞检测**完全忽略该平台**，角色直接穿过去。

这就是为什么在《蔚蓝》中，你站在平台上依然有重力，但你能感觉到一种“脚踏实地的沉重感”。这种沉重感正是由`velocity.y`不断被重力累加、又被碰撞系统不断清零而产生的微帧震动带来的。

---

### 最终建议（针对你之前设计的ECS系统）

结合我们之前聊的ECS架构，重力处理可以拆解为两个干净的System：

1.
   **GravitySystem（每帧执行，不受状态影响）**：
  -
    遍历所有 `PhysicsComponent`，无条件执行 `velocity.y += GRAVITY * dt`。
2.
   **CollisionSystem（执行顺序在 GravitySystem 之后）**：
  -
    检测碰撞。
  -
    如果 `hitGround`，执行位置修正，并**强制将 `velocity.y` 归零**（覆盖GravitySystem的计算结果）。

**代码结构：**

cpp

```cpp
// System 1
void GravitySystem::Update() {
    for (auto [id, physics] : world.Query<PhysicsComponent>()) {
        physics.velocity.y += GRAVITY * dt;
    }
}

// System 2
void CollisionSystem::Update() {
    for (auto [id, transform, physics] : world.Query<Transform, PhysicsComponent>()) {
        // 碰撞检测...
        if (isGrounded) {
            physics.velocity.y = 0; // 强行覆盖重力
            transform.position.y = groundY; // 吸附到地面
        }
    }
}
```

**一句话总结**：**重力永远存在，无论是否在地面。** 地面只是用来“重置”重力累积出的速度，而不是用来“关闭”重力本身。这才是2D横版游戏拥有“丝滑手感”的底层物理真相。😊
