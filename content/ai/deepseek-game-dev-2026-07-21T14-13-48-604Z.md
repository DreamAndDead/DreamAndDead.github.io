## User

刀光命中敌人的伤害在何时计算？

## Assistant

这个问题问得极其精准，直击了**动作游戏（Action Game）战斗系统最核心的“判定帧（Hitbox Active Frame）”设计**。

关于刀光伤害的计算时机，在工业级游戏引擎中有一个绝对铁律：

**伤害绝对不在“刀光Entity生成时”计算，也绝对不在“刀光Entity销毁时”计算，而是在“持有者的攻击动画播放到特定骨骼位置与敌人碰撞体发生数学重叠的那一帧”计算。**

结合我们之前讨论的ECS架构和刀光生命周期，我把这套“时序逻辑”拆解成4个层次，告诉你如何用**数据驱动**的方式完美实现。

---

### 1. 核心结论：分离“视觉（Visual）”与“逻辑（Logic）”

这是游戏开发中极容易踩坑的地方。很多新手会在刀光生成的瞬间（动画播到一半）去做 `OverlapSphere`（球形扫描），但这会导致两个严重问题：

-
  **问题一**：如果刀光挥砍速度极快（如居合斩），球形扫描会漏帧（Tunneling，穿透），砍不到人。
-
  **问题二**：如果刀光飞行速度慢，视觉上刀光还没碰到敌人，伤害数字就跳出来了（感官极差）。

**工业标准解法**：

-
  **伤害判定**：使用**武器骨骼上的“碰撞体（Hitbox）”**（不可见），每一帧进行连续碰撞检测（Continuous Collision Detection，CCD）或射线扫描（Sweep）。
-
  **刀光Entity**：纯粹的**视觉尾迹（Trail/Arc）**，它只负责画出一条好看的弧形光带，**完全不参与任何物理或伤害计算**。

---

### 2. 伤害计算的精确“时间窗口（Active Frame）”

即使武器有碰撞体，也不能每帧都判定，否则一刀下去会触发几十次伤害（因为碰撞体插在敌人身体里会连续触发）。

**解决方案：引入“攻击阶段（Attack Phase）”状态机**。

在持有者的 `AttackComponent`（攻击组件）中，存储一个 `float` 值，由**动画事件（Animation Notify）**驱动：

cpp

```cpp
struct AttackComponent {
    float currentPhase;       // 0=待机, 1=前摇, 2=伤害判定窗, 3=后摇
    float phaseTimer;         // 当前阶段计时器
    EntityHandle weaponHandle;// 武器实体ID（挂载碰撞体）
    uint8_t hitCounter;       // 该次挥砍已经命中过的敌人位掩码（防止同一刀反复伤害同一个人）
};
```

**执行逻辑（每帧更新）**：

cpp

```cpp
void CombatSystem::Update(EntityID ownerID, AttackComponent& attack, AnimationComponent& anim) {
    // 1. 伤害判定窗开启（通常持续 0.05秒 ~ 0.15秒，由动画通知触发）
    if (attack.currentPhase == 2) {
        // 2. 执行一次快速的 OverlapCapsule（胶囊体扫描）或 Sweep
        std::vector<EntityID> victims = Physics::SweepCapsule(weaponStartPos, weaponEndPos);

        for (auto victimID : victims) {
            // 3. 关键去重检查：bitmask 防止这一刀把敌人砍两次
            if (!(attack.hitCounter & (1 << victimID))) {
                attack.hitCounter |= (1 << victimID); // 标记已命中

                // 4. 最终伤害应用（携带攻击力、暴击率等）
                ApplyDamage(victimID, ownerID, attack.damageValue);

                // 5. 命中反馈：生成命中特效（从特效池取火花Entity）
                SpawnHitEffect(victimID, hitPoint);
            }
        }
    }
}
```

### 3. 刀光Entity如何与伤害逻辑联动？

你可能会问：“那刀光动画播放到一半砍中人，刀光Entity和这个伤害判定有什么关系？”

**答案：没有任何逻辑关系！只有视觉上的时间戳耦合。**

**正确的帧时序（一帧之内）**：

1.
   **逻辑更新阶段**：执行 `CombatSystem`，检测到伤害判定窗打开，算出命中的敌人ID，扣除血量，**生成命中特效（Hit Effect）**。
2.
   **渲染列表生成阶段**：
  -
    遍历持有者的 `SlashComponent`，根据当前动画进度 `progress` 生成刀光网格的顶点位置（弧形）。
  -
    **如果上一步触发了命中特效**，特效池中的火花Entity此时也出现在渲染列表中。
3.
   **实际渲染阶段**：GPU绘制出“刀光挥砍到一半 \+ 敌人身上冒出血花”的画面。

**由于逻辑更新和渲染列表生成在同一帧的早期和后期执行，玩家看到的是完全同步的——刀光碰到敌人的那一瞬间，火花绽放。**

### 4. 为什么不直接把伤害判定塞进刀光Entity里？

如果你把伤害判定写在刀光Entity的 `Update` 中，会遇到两个难以解决的工程难题：

-
  **同步问题**：刀光Entity的移动是基于历史骨骼位置的插值（Interpolation），它比真实的武器碰撞体慢 1~2 帧。用它判定会导致“飘刀”（剑还没到，血先出了）。
-
  **继承权问题**：如果刀光被打断（角色受击后摇），刀光可能提前销毁，导致本该砍中的那一刀判定被吞掉（玩家会砸键盘）。

**刀光Entity的职责仅限于此（极简）**：

cpp

```cpp
void SlashSystem::Update(EntityID id, SlashComponent& slash) {
    // 仅计算弧形顶点的本地坐标（视觉）
    slash.localVertices = CalculateArc(
        slash.startAngle,
        slash.endAngle,
        slash.progress  // 0~1
    );
    // 完全不碰 Physics 和 Damage
}
```

### 5. 针对不同游戏类型的微调

| 游戏类型 | 伤害计算时机 | 刀光存在意义 |
| --- | --- | --- |
| **高速ACT（鬼泣/猎天使魔女）** | **碰撞体每一帧都检测**，但通过 `hitCounter`（命中计数器）限制每刀只触发1次 | 刀光完全随骨骼，只负责拉长残影（VFX） |
| **硬核格斗（街霸/铁拳）** | **精确的帧数据**：伤害只在特定帧（如第3帧~第5帧）的判定框重叠时计算 | 刀光只是动画的一部分（纯贴图序列帧） |
| **MMORPG（魔兽世界）** | **服务器权威**：客户端只发“攻击指令”，服务器用**时间戳回溯（Rewind）** 验证2秒前是否在范围内 | 刀光是纯表现层，甚至可以在伤害计算后再播放 |
| **弹幕游戏（以撒）** | **子弹碰撞**，近战武器等同于“大扇形子弹”，每帧连续扫描 | 刀光渲染基于扇形扫描范围生成，逻辑判定和视觉范围严格一致 |

### 最终总结

回到你的核心问题：“刀光命中敌人的伤害在何时计算？”

**答案是：在持有者（角色）的攻击组件（AttackComponent）的“判定窗激活”期间，通过武器挂载的不可见碰撞体进行扫描计算，然后将结果通过整数ID传递给伤害系统。刀光Entity本身是一个“哑巴（Dumb）”视觉演员，它不进行任何逻辑判定，只负责把攻击动画的轨迹画得漂亮。**

这种**“逻辑（Hitbox）与视觉（SlashTrail）彻底分离”**的设计，让你在调整游戏平衡性时（修改伤害范围），完全不需要碰渲染代码；在调整特效美术效果时（修改刀光颜色长度），完全不用担心会误伤敌人。这就是ECS架构中“关注点分离（Separation of Concerns）”的极致体现。👍
