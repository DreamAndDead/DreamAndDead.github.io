## 编译时检查 vs 运行时检查：核心区别

这是编程语言设计中最重要的概念之一。编译时检查在**代码编译期间**进行，运行时检查在**程序运行期间**进行。它们的取舍直接影响程序的**安全性、性能和开发效率**。

---

### 1. **核心区别对比**

| 对比维度 | 编译时检查 \(Compile-time\) | 运行时检查 \(Runtime\) |
| --- | --- | --- |
| **发生时间** | 编译阶段（代码还没运行） | 程序执行阶段 |
| **错误发现时机** | 开发阶段（早） | 上线后/测试时（晚） |
| **性能开销** | **无**（编译完成就消失了） | **有**（每次执行都要检查） |
| **能检测什么** | 语法错误、类型错误、模板实例化等 | 逻辑错误、资源不足、用户输入异常等 |
| **错误处理** | 编译失败，无法生成可执行文件 | 抛出异常、返回错误码或崩溃 |
| **典型例子** | 类型不匹配、未定义变量、静态断言 | 数组越界、空指针解引用、`dynamic_cast` 失败 |

---

### 2. **编译时检查的具体例子**

#### 2.1 类型检查（强类型语言的核心）

cpp

```cpp
int a = 10;
std::string s = "hello";
a = s;  // ❌ 编译错误！int 和 string 类型不匹配
```

#### 2.2 语法检查

cpp

```cpp
int x = 10  // ❌ 编译错误！缺少分号
```

#### 2.3 静态断言（C\+\+11）

cpp

```cpp
static_assert(sizeof(int) == 4, "int 必须是4字节！");  // ✅ 编译时检查
// 如果条件不满足，编译失败
```

#### 2.4 模板实例化检查

cpp

```cpp
template<typename T>
void process(T value) {
value.foo();  // 编译时检查 T 是否有 foo() 成员函数
}

struct A {};
struct B { void foo() {} };

process(A());  // ❌ 编译错误！A 没有 foo()
process(B());  // ✅ 编译通过
```

#### 2.5 constexpr 表达式（C\+\+11）

cpp

```cpp
constexpr int square(int x) {
return x * x;
}

int arr[square(5)];  // ✅ 编译时计算，arr 大小是 25
// 等价于 int arr[25];
```

### 3. **运行时检查的具体例子**

#### 3.1 数组越界（C\+\+ 不检查，但有些语言检查）

cpp

```cpp
int arr[5] = {1, 2, 3, 4, 5};
int x = arr[10];  // ⚠️ 编译通过！运行时可能崩溃（未定义行为）

// Java 会检查：
// int[] arr = new int[5];
// int x = arr[10];  // 编译通过，运行时抛出 ArrayIndexOutOfBoundsException
```

#### 3.2 空指针解引用

cpp

```cpp
int* ptr = nullptr;
*ptr = 10;  // ⚠️ 编译通过！运行时崩溃（段错误）
```

#### 3.3 动态类型转换失败

cpp

```cpp
class Base { virtual ~Base() = default; };
class Derived : public Base {};
class Other {};

Base* base = new Base();
Derived* d = dynamic_cast<Derived*>(base);  // ✅ 编译通过
if (d == nullptr) {  // 运行时检查失败，d == nullptr
std::cout << "转换失败！\n";
}
```

#### 3.4 除法溢出

cpp

```cpp
int divide(int a, int b) {
return a / b;  // ✅ 编译通过
}

divide(10, 0);  // 运行时崩溃（除零错误）
```

#### 3.5 文件操作失败

cpp

```cpp
std::ifstream file("nonexistent.txt");
if (!file.is_open()) {  // ✅ 编译通过，运行时检查
std::cout << "文件打开失败\n";
}
```

#### 3.6 动态内存分配失败

cpp

```cpp
try {
int* huge = new int[1000000000000LL];  // 编译通过
} catch (const std::bad_alloc& e) {  // 运行时可能抛出异常
std::cout << "内存分配失败\n";
}
```

### 4. **C\+\+ 中的静态多态 vs 动态多态**

这是编译时检查和运行时检查的典型对比：

#### 4.1 编译时多态（模板）

cpp

```cpp
template<typename T>
void print(T value) {
std::cout << value << '\n';  // 编译时确定 T 的类型
}

print(10);    // 实例化 print<int>
print("hi");  // 实例化 print<const char*>
// ✅ 编译时完成，无运行时开销
```

#### 4.2 运行时多态（虚函数）

cpp

```cpp
class Base {
public:
virtual void print() { std::cout << "Base\n"; }
};

class Derived : public Base {
public:
void print() override { std::cout << "Derived\n"; }
};

Base* ptr = getObject();  // 运行时才知道具体类型
ptr->print();  // 运行时通过 vtable 查找函数地址，有开销
```

### 5. **静态断言 vs 动态断言**

cpp

```cpp
// 编译时断言
static_assert(sizeof(int) == 4, "int 必须是4字节");
// 编译时检查，失败则编译不通过

// 运行时断言
#include <cassert>
int x = getValue();
assert(x > 0);  // 运行时检查，失败则程序终止
// 在 Release 模式下，assert 会被禁用（NDEBUG 宏）
```

### 6. **如何选择？**

| 场景 | 推荐检查方式 | 原因 |
| --- | --- | --- |
| **类型安全** | 编译时 | 无性能开销，尽早发现问题 |
| **数组边界** | 编译时（如果可以） | C\+\+ 用 `std::array` 或编译期常量 |
| **空指针** | 运行时 | 有些指针只能在运行时确定 |
| **用户输入验证** | 运行时 | 输入只能在程序运行时获得 |
| **文件操作** | 运行时 | 文件是否存在只能在运行时检查 |
| **网络连接** | 运行时 | 外部资源状态无法在编译时确定 |
| **数学运算** | 运行时 | 输入值决定是否溢出 |
| **模板参数** | 编译时 | 模板参数必须在编译期确定 |

---

### 7. **设计原则：尽可能将检查移到编译时**

cpp

```cpp
// ❌ 运行时检查（有性能开销）
int array_size;
std::cin >> array_size;
int* arr = new int[array_size];
// 如果 array_size 是 0 或负数？运行时可能崩溃

// ✅ 编译时检查（零开销）
constexpr int ARRAY_SIZE = 10;  // 编译期常量
int arr[ARRAY_SIZE];  // 完全安全
static_assert(ARRAY_SIZE > 0, "数组大小必须大于0");
```

**现代 C\+\+ 的趋势：**

-
尽可能使用 `constexpr`、`consteval` 进行编译期计算
-
使用 `static_assert` 代替运行时 `assert`
-
使用模板（编译时多态）代替虚函数（运行时多态）
-
使用 `std::array` 代替 C 风格数组
-
使用 `std::optional`、`std::expected` 明确处理可能失败的情况

### 8. **真实案例：性能对比**

cpp

```cpp
#include <chrono>
#include <iostream>

// 运行时检查版本
int divide_runtime(int a, int b) {
if (b == 0) throw std::runtime_error("division by zero");
return a / b;
}

// 编译时检查版本（通过模板）
template<int Denominator>
int divide_compiletime(int a) {
static_assert(Denominator != 0, "Denominator cannot be zero!");
return a / Denominator;
}

int main() {
// 运行时检查（每次调用都检查）
auto start = std::chrono::high_resolution_clock::now();
for (int i = 0; i < 10000000; ++i) {
try {
divide_runtime(i, 2);
} catch (...) {}
}
auto end = std::chrono::high_resolution_clock::now();
// 耗时：约 50ms（有分支预测和异常处理开销）

// 编译时检查（零开销）
start = std::chrono::high_resolution_clock::now();
for (int i = 0; i < 10000000; ++i) {
divide_compiletime<2>(i);  // 完全内联，无任何检查
}
end = std::chrono::high_resolution_clock::now();
// 耗时：约 10ms（快了 5 倍！）
}
```

### 9. **总结对比表**

| 检查类型 | 优点 | 缺点 | 典型应用 |
| --- | --- | --- | --- |
| **编译时检查** | 零开销、早发现问题、更高性能 | 不能检查动态数据 | 类型系统、模板、`static_assert`、`constexpr` |
| **运行时检查** | 灵活、能处理动态数据 | 性能开销、问题发现晚 | 用户输入、文件操作、网络、动态内存 |

---

### 核心原则

> **能编译时检查就编译时检查，必须运行时检查才运行时检查。**

**记忆口诀：**

> **编译检查保安全，零开销来跑得欢**
> **运行检查解动态，性能损耗要考虑**
> **类型模板静态断，编译完成就心安**
> **输入文件网络错，运行时刻才能判**
